# OpenMES 学习路线

可以先打开[交互学习页面](openmes-course/index.html)，按六章追踪生产链，最后填写 M1 设计草稿。

先读[项目地图和核心调用链](openmes-implementation-guide.md)，再看下面的重建顺序。目标是亲手走通一条最小生产链，从工单接收到最后一道工序回写产量。

OpenMES 同时包含生产、排程、质量、仓储和设备接入等子系统，整体采用 `read-through`。本次有意延后重建骨架，[`learning-kit.yaml`](learning-kit.yaml) 中的里程碑用于核验源码与运行环境。下面的 M1–M7 是后续练习路线。

## 重建里程碑

首轮只选单产线、固定顺序、整批流转（`whole_batch`）。每行描述后续要验证的现象，具体接口、测试断言和练习范围在你提出设计后逐项定稿。

| 阶段 | 你先设计什么 | 验收方向 |
| --- | --- | --- |
| **M1 · 工单与接收** | 工单最小字段、创建与接收的状态规则、失败如何表达 | 合法创建和接收成功。缺少必填信息、数量非法、工单号冲突或不允许的接收动作有明确结果，已有状态保持一致 |
| **M2 · 工艺快照与建批** | 模板与快照的边界、批次编号、工序如何由快照产生 | 创建工单后修改模板，按该工单生成的批次仍使用原快照。建两批时身份可区分，批次状态各自独立 |
| **M3 · 顺序执行与产量汇总** | 开始与完成的前置条件、工序／批次／工单各自何时完成、产量从何处汇总 | 两道工序按序完成。首道完成只推进下一道，末道完成才结算该批产量。多批累计未达计划时工单保持可生产，重复完成不会重复计产 |
| **M4 · 持久化与请求入口** | 请求校验、产线授权和业务事务的边界，以及失败后能否重试 | 通过一个入口走通 M1–M3。跨产线操作被拒绝，模拟写入中途失败后无部分提交，重试与并发不会重复结算。并发场景使用能验证相应锁语义的数据库 |
| **M5 · 按量流转** | 单独扩展 `transfer`，定义工序间的在途、通过、报废和可用量 | 上游只交出部分数量时下游可按量生产，超量被拒绝。报废与结存可核对，末工序通过量和工单汇总一致 |
| **M6 · 物料分配与追溯** | 选一种领用时点，定义物料批、分配、实耗与生产批的关联 | 数量可核对，物料不足时没有半笔分配，能从成品批追到实际使用的物料批 |
| **M7 · 质量阻塞** | 选一种阻塞式质检，定义它约束哪个对象、由谁解除 | 待检时阻止对应生产动作，满足放行条件后可继续，重复提交保持一致 |

M1 → M2 → M3 → M4 构成首轮闭环。M5–M7 是闭环后的候选练习，一次选一个。ERP、排程、设备协议、实时同步和多端 UI 先通过项目地图定位，等有具体学习目标时再单独拆题。

## 每个里程碑怎么进行

1. **你先提设计。** 简述目标和范围、对象及状态、关键动作的输入输出、一个成功例子和两个失败例子。遇到拿不准的规则，可以写出你的取舍。
2. **我检查设计。** 先给结论，按优先级指出遗漏和取舍，区分必须补齐的行为与可留待后续的复杂度。你补齐关键问题后再进入练习。
3. **我发当期练习。** 只提供必要的文件结构、空实现与运行命令。骨架契约测试应先通过，本期行为测试应因明确的待实现行为而失败。提示按需给出，一级指出该检查的约束，二级缩小到相关对象或边界，三级给可手推的最小案例。
4. **你提交代码，我验收。** 运行本期测试和此前的回归测试，检查正确性、边界情况和设计质量。若有问题，给出复现与复验条件。通过后再对照原仓库的对应实现，写一句差异与理由，然后进入下一阶段。

练习时先写出期望输入输出，每次跑一组测试。对应的源码实现留到验收通过后对照。讲解先给结论，细节随追问展开。

## 完成标准

- **导读完成**。能用自己的话画出工单、批次和工序的关系，沿一次完成工序请求指出入口、规则和写入位置，并解释两种流转模式的区别。环境检查通过或有明确的跳过记录。
- **首轮重建完成**。M1–M4 逐关通过，能演示两道工序从开工到产量回写，并说明一次失败如何做到状态与产量一致。

## 从 M1 开始

下一次先提交一份简短设计。写下你认为工单必须保存哪些信息、接收动作允许从什么状态发生、工单号重复和同一工单被再次接收分别怎么处理。附一个正常例子和两个拒绝或重试例子即可。
