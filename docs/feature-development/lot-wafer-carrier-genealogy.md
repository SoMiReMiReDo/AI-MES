## 3. 身份、基线与数量权威源

### 3.1 身份与归属

- LotNumber：厂区内唯一，长度沿用现有 64；WaferCode：实例内唯一，长度 64；CarrierCode：实例内唯一，长度 64。大小写沿用当前数据库精确匹配，输入去首尾空白；规范化后再校验及计算幂等摘要。
- WaferCode 是永久身份；供应商片号、物料来源批号、载具槽号均不能替代。编码创建后不可改，不提供物理删除。
- 新增 Wafer 的稳定 `FabId`、`WorkOrderId`；建片时从工单写入，首版不允许变更。历史查询不依赖当前成员是否仍存在，也不通过当前载具推断厂区。
- 同一 Wafer 同时最多一个有效 LotMembership；有效区间为 `[ValidFrom, ValidTo)`。拆合批用同一业务时刻 T 关闭旧归属并建立新归属，`ChangeEventId` 表示创建该归属的血缘事件，不覆盖旧行的创建事件。
- Lot 固定 `WorkOrderId + SnapshotVersion`，以工单下达快照解析产品修订和路线；不能根据产品“当前默认路线”重新选择。拆合批目标继承相同基线。

### 3.2 数量口径

| 字段/指标 | 权威来源与含义 |
| --- | --- |
| TargetQty | Lot 创建时的片数基线；拆合批后不靠改它伪装数量，子批/合成批以创建片数记录 |
| currentWaferCount | 当前有效成员数；完成片允许保留最终 Lot 归属，因此不等于在制量 |
| inProcessQty | 已首次投放、尚无完成/报废终结事实的唯一 Wafer；含等待、加工和阻塞 |
| releasedQty | 稳定属于工单且已有首次投放事实的唯一 Wafer；拆合批不重复新增 |
| completedQty / ProducedQty | 可信终点完成事实按 Wafer 去重；Lot/工单字段仅为同事务维护、可重算的缓存 |
| scrapQty | F6 逐片 Scrap 处置；区分处置时 Lot 与工单稳定归属，不相加当前及历史成员 |
| transferredInQty / transferredOutQty | 按血缘明细分别计转入/转出，表示迁移次数，不是新投片或产量 |

现有 `production.lot_quantities` 仅提供当前成员数与处置时 Lot 的报废数，不能直接作为 WIP 或工单进度。未完成 F5/F6 集成的指标返回 null 和缺失依赖，不用 0 冒充真实结果。

本文建议首版投放不得超过工单 PlannedQty：工单锁内核对“已有首次投放唯一片数 + 本次新增投放片数”。草稿登记不占投放额度，报废不自动释放额度，补投/超投审批预留。此项是设计策略，并非用户已确认的现场产量政策。

## 4. F4-01 建批与晶圆登记

创建输入为已下达工单、可选 Lot 编号、优先级、备注及完整 Wafer 清单。Fab、产品修订、路线、快照版本由服务端解析；不接收客户端自由选择。LotType 首版为 Production。

1. 校验工单可见且 Released，快照存在、可解析且与工单一致；产品/路线仍可用于新投批。失效/废止不自动改为新版本。
2. 清单至少一片，片号去重，WaferSizeMm 为正且同批一致；尺寸是登记值，不冒充已验证设备能力。首版只创建新 Wafer 身份；既有 Wafer 转入必须走拆合批，不能借“登记”绕过血缘。
3. `originMaterialLotId`、`supplierWaferCode` 可空；填写时必须解析材料关联及访问范围。无厂区归属的物料主数据按单厂实例共享规则授权；具 Warehouse 的批次沿 Warehouse 校验厂区。来源已冻结/失效则拒绝新引用；完整检验门禁仍依赖 F8/F6。
4. 有编号则校验唯一；无 Lot 编号时复用 F2 的 Lot 编号规则，在同事务分配。Wafer 清单使用明确片号，自动片号模板另行扩展，不把槽号拼成片号。
5. 同事务写 Draft Lot、Registered Wafers、Create 血缘事件（FromLotId=null）、逐片明细和初始归属，以及审计、业务事件、成功回执。任何失败全部回滚。

首版建批后不提供增删片或替换身份入口；Draft 可编辑优先级与备注。登记错误可取消未投放批后用新身份重建，取消片号继续保留；永久身份纠错需要独立受控方案，不通过复用片号覆盖历史。

## 5. F4-02 投放与状态模型

### 5.1 投放

Draft → Ready：复核工单 Released、同一快照、产品/路线当前有效、片清单与归属完整、片状态 Registered、无有效 Hold/停工及已启用门禁阻塞；核对投放额度。使用绑定路线按 SequenceNo 排序的首个步骤，不接受客户端指定起点或跳站。

同事务写 Lot.ReleasedToRouteAt/By、CurrentRouteStepId，Wafer → Active 及不可变首次投放事实，创建首个 Waiting StepExecution，保存该步骤作业定义引用并写审计/事件/回执。步骤进入时间表示排队，Lot.StartedAt 留给 F5 首次实际 Track-in。F4 的投放不是 `quality.lot_releases` 质量放行，也不解除 Hold。

投放不默认要求装载；装载是独立物理记录。若现场工序要求载具，必须由 F5 的已启用门禁校验，不能由本设计推断所有设备都允许散片。

### 5.2 生命周期与动作

| 对象/状态 | 进入条件 | 允许动作与退出 |
| --- | --- | --- |
| Lot Draft | 原子建批成功 | 改备注/优先级、载具操作、投放或取消 |
| Lot Ready | 投放、拆合批继承等待位置或 F5 非终点退出 | 无阻塞时等待 Track-in；符合第 7 节时拆合批 |
| Lot Running | F5 成功 Track-in | F5 Track-out/受控中止；禁止成员及载具变更 |
| Lot AwaitingDisposition | F5 中止/未通过且需处置 | F5/F6 受控处理；禁止投放、拆合批和普通完工 |
| Lot Completed | 余下有效片均有可信终点完成事实，且本批完成片数大于 0 | 生产终态；仍允许授权成品载具操作，保留归属 |
| Lot Merged | 全部有效片已整体合入新批 | 终态，当前成员为 0，不计完工 |
| Lot Cancelled | 从未投放的 Draft 按原因取消 | 终态，关闭归属/装载，片标 Cancelled，不计报废或完工 |
| Lot Closed | F6 全片报废后收尾，CloseReason=AllScrapped | 终态，无有效成员，完成量为 0；不提供通用人工关闭捷径 |
| Wafer Registered / Active | 建片 / 首次投放 | 拆合批只改归属，不改变 Active |
| Wafer Completed / Scrapped / Cancelled | F5 终点 / F6 报废 / 未投放取消 | 首版终态，保留身份与历史，不重新投放 |

状态名是待实施枚举，当前字符串列不代表已保护以上转换。Hold 是独立叠加事实，UI 显示“Ready + Hold”等组合；解除一条 Hold 不改生命周期，也不能消除其它阻塞。

## 6. F4-03 载具、槽位与位置

载具创建指定编码、类型、容量、适用晶圆尺寸和可选当前位置；一次创建 1～容量的槽位。类型及尺寸先作为演示配置，不宣称 FOUP/卡匣或真机标准兼容。本文建议尺寸为单一允许值；相应字段尚需迁移。

首版状态为 Available/Disabled；停用要求无在载片。编码、厂区、类型、容量及尺寸建成后固定，状态可维护；扩容或类型更正另行设计，不能删除有历史的槽位。Location 必须属于部署 Fab 且启用，历史可显示已停用位置。

装载、卸载和换槽/换载具统一为原子装载命令：每片提交预期原槽位（未装载为 null）及目标槽位（卸载为 null），不得全部为空或原地无变更。全部校验成功后先关闭所有受影响旧装载，再建立新装载，以支持两片互换槽位。

- 一片同时最多一槽，一槽同时最多一片；目标槽位必须存在且容量/尺寸兼容，目的载具 Available。
- 每片所属 Lot、源/目标载具、位置必须同厂；Registered、Active、Completed 片可操作，Cancelled/Scrapped 禁止普通装载。
- 任一受影响片或移动载具内的片处于 Running/有效 Run 占用时拒绝；AwaitingDisposition 或有效 Hold 默认也拒绝普通人工变更，专门质量处置由 F6 编排。
- 允许同载具存放多个 Lot 的同尺寸片，也允许一个 Lot 分布多个载具。载具不拥有生产归属，拆合批不会自动换槽或搬运。
- 装卸只改变 CarrierLoad；载具人工移位必须使用独立命令，同时追加 CarrierMovement 并更新 CurrentLocationId。移位不改变步骤或 Lot 状态；空载具也保留移位历史。
- 操作者和原因由同事务审计/业务事件关联到具体装载记录。时间由服务端生成，禁止浏览器回填历史；区间结束必须严格大于开始，快速连续命令使用锁内单调业务时间，至少跨过数据库时间精度，不能制造零长区间。

Carrier 详情同时显示槽号、Wafer、当前 Lot、状态与来源链接。无当前位置显示“位置未登记”；不把移位登记当作实际搬运确认或设备联机事件。

## 7. F4-04/05 拆合批

### 7.1 兼容矩阵

首版进一步收敛到已投放 Ready 且当前步骤 Waiting；Draft 可取消重建，Running、AwaitingDisposition 及终态不拆合。相同工艺位置定义为同一 RouteVersionId、CurrentRouteStepId，且各自处于正常路线的等待阶段；不能只按工序名判断。

| 校验 | 拆批 | 合批 |
| --- | --- | --- |
| 同厂、已下达工单、稳定工单归属 | 源批及全部选片一致 | 所有源批和所有片一致 |
| 产品修订、路线、工单快照 | 目标完整继承 | 必须完全相同，不自动升级 |
| 晶圆尺寸 | 继承源批一致的尺寸 | 全部源片尺寸一致，不能仅凭产品相同假定兼容 |
| 当前步骤及执行事实 | 无 Running Run、无待处置异常 | 等待位置一致，各源步骤均无实际启动 |
| Hold/已启用门禁 | 任一有效 Hold 或阻塞均拒绝 | 任一源有阻塞即全部拒绝 |
| Recipe 与特殊流程 | 继承基线，不复制实际 Run | 不存在互斥的适用约束；F5 再验证实际设备/Recipe |
| 返工/Q-time/特殊路线 | 若存在未支持的返工或活动 Q-time 上下文则拒绝 | 不凭“当前位置相同”丢失上下文 |
| 载具 | 保持逐片原槽位 | 保持逐片原槽位，可能出现载具内多 Lot |

Recipe 不在拆合批时提前固定。所有源批须具有相同工艺约束基线；未接通的设备适用检查要在覆盖信息中标缺，不能宣称目标批已具备 Track-in 条件。版本后续废止不改历史绑定；拆合批只继承既有 WIP 基线，是否允许继续加工由 F5 门禁决定。

### 7.2 拆批算法

请求包含源 Lot、严格非空且小于源当前片数的 Wafer 子集、新批编号及原因；一次产生一个新批，源批至少留一片。全量转批、一次多目标拆分不作为首版入口。

锁内重新读取集合 S 和选片 M，要求 M 无重复且 M 为 S 的真子集；写 Split 事件及每个迁移片的 FromLot/ToLot；在 T 关闭 M 的旧归属，建立新归属。源批保留 `S−M`，新批持有 M；两集合无交集，并集恰为 S。

目标继承工单/快照、产品、路线、优先级和等待位置，创建自己的 Waiting StepExecution，记录继承来源步骤。源等待步骤保留；原过站、点检、量测、实际 Recipe 留在原记录上，沿血缘查阅，不能复制为新批加工事实。新批记录此次创建/继承时间；每片最初投放时间从首次投放事实读取。

新批 ReleasedToRouteAt/By 记录本次继承进入路线的时间/操作者，不冒充逐片首次投放；StartedAt 留空，直到新批自己的首次实际 Run。合批新批采用相同时间规则；本文设计合批优先级取源批最高值，预览明确展示该结果并记入审计，不改变工单优先级。

### 7.3 合批算法

请求至少两个不同源批，提交每个源批版本与预期完整片清单、新批编号及原因。首版全部源批合入新批，避免一个目标既是源又产生自环。

锁内验证兼容矩阵及片清单，要求源集合两两不相交；写 Merge 事件和逐片明细，同一 T 关闭所有源归属并建立目标归属。关闭源 Waiting StepExecution 为 Transferred（不是 Completed），源 Lot → Merged，清空 CurrentRouteStepId；新批 Ready，并创建继承等待步骤。

源当前片数为 0，新批片数为所有源集合并集大小；Wafer ID、稳定工单、首次投放、载具占用不变。来源步骤可多对一，需保存继承关联，不能只用一个 ParentLotId。

## 8. F4-06 收尾、完工与更正

取消只支持未投放 Draft：要求无有效 Hold、无步骤/加工事实；原子卸载、关闭成员、标记片和 Lot Cancelled，记录原因及关闭时间。取消不回收片号、不删除 Create 血缘，不认定报废。工单取消仍遵守 F3 的“存在任何关联 Lot 则拒绝”，取消 Lot 不自动改变工单状态。

终点完工由 F5 最后一步成功 Track-out 在同事务调用内部 `CompleteAtRouteEnd`：逐片验证参与事实、路线终点、输出/质量门禁和稳定工单归属，写一次性 WaferCompletion，Wafer.ProducedAt 及 Completed 状态；Lot 剩余片全部完成时写 CompletedAt 和 ProducedQty。终点未到、Run 未关闭、待处置或 Hold 阻塞时拒绝普通完工，不能提供“手工填完成量”替代。

完成保留最终 LotMembership 和装载，便于成品追溯；统计必须排除 Completed，不能以归属存在推断在制。若部分片之前已报废，完成量仅计实际完成片。全部报废则由 F6 原子关闭归属/装载并使 Lot Closed/AllScrapped，不伪造 CompletedAt。

合批耗尽只表示转移；Merged、Cancelled、Closed 的收尾时间用拟增 ClosedAt/CloseReason，不能混用 CompletedAt。所有终态只读生产字段，完成片可继续做符合第 6 节的载具操作。

首版不提供任意回滚历史或完工撤销。更正申请必须带原事实 ID、原因与影响片集，由对应模块设计补偿命令并追加记录；血缘、加工、报废和完成事实不能覆盖。取消/拆合批重放由幂等回执处理，不算更正。启用返工和完成撤销前需重新定义唯一完工及补偿统计。

## 9. 事务、并发、审计和授权

所有 F4 写入经同一应用授权入口。权限与 Fab 范围同时满足；Wafer 依稳定 Fab 授权，载具沿 Carrier.FabId，血缘事件检查全部关联 Lot，成员沿 Lot 与 Wafer 双向校验，步骤沿 Lot。统计/分页前过滤，不可见对象返回 404。

F4 需要 `production.lots.read/create/manage/release/split/merge/cancel`、`production.wafers.read`、`production.genealogy.read`、`production.carriers.read/manage/load/move`。权限是设计中的新增项；角色只聚合权限，不自动获得生产动作。面向建批的工单/路线候选查询仍检查 F3/F2 读取权限；命令内部依赖校验不要求操作者具备工程维护权限。

一次写命令：会话/防伪 → 事务与既有写锁 → 当前权限与对象范围 → 幂等结果核对 → 版本与当前集合/占用复核 → 业务规则 → 事实/审计/业务事件/回执 → 提交。重放前重新授权；成功重放先于旧 ETag 检查，不因首次命令推进版本而失败。

多对象动作显式提交各 Lot/Carrier 的预期版本；所有成员、Hold、占用变化须推进相关聚合版本。即使 Carrier 版本匹配，也须锁内重查 Wafer 当前 Lot、生命周期及原槽位。未来移除全局锁时统一顺序为权限协调锁 → 工单 ID 排序 → Lot ID 排序 → Carrier ID 排序 → Wafer ID 排序 → 步骤/Run → 编号资源；发现新对象集合则重新开始事务，不倒序补锁。F5/F6 必须遵守同一协议。

归属关闭同样遵守严格正时间区间：锁内取不早于当前时间且晚于所有待关闭区间起点的统一 T，按数据库时间精度递增后用于该命令全部旧区间结束、新区间开始及事件时间。完成/报废的逐片唯一约束冲突须校验是否为同一事实重放，不得把不同 Run 的冲突解释为成功。

所有生产动作使用 Idempotency-Key，作用域含用户、Fab、动作和目标；摘要覆盖规范化载荷及预期版本，集合按稳定 ID 排序，装载映射保持片与槽的对应。当前制造后端摘要为原始 JSON，不能直接视为已满足此契约，需 F4 代码阶段补充共享实现并回归 F2/F3。

GenealogyEvent 现有 IdempotencyKey 是全局唯一；不能直接写入客户端局部键。设计采用服务端内部命令 ID（成功回执 ID）作为血缘键，客户端键仍存 CommandReceipt，并在事件载荷关联回执。不同用户/动作复用同一客户端键不会误冲突。

业务事实、审计、BusinessEvent 与成功回执同事务；事务失败无半成品。BusinessEvent 保存 schemaVersion、commandId、对象/片集、前后状态、基线与来源事件 ID。未启用消费者时不靠 Outbox 更新关键数量；后续 F12 投递与通知可以至少一次消费，但不能影响已提交事实的正确性。

## 10. 数据差异与迁移设计

以下全部为拟增/待加固项，本轮不执行迁移；[实际字典](../development-process/05-database-catalog.md)继续只描述已存在结构。

| 项目 | 现有缺口 | 设计补充与约束 |
| --- | --- | --- |
| Wafer 稳定归属 | 无 FabId/WorkOrderId | 新增稳定字段及外键；首版新建必填，跨 Lot 校验同工单/厂区；禁止静默改归属 |
| 首次投放事实 | Lot 时间不能覆盖拆合批后的逐片起点 | 拟增 `WaferRelease`：WaferId 唯一、WorkOrderId、InitialLotId、SnapshotVersion、RouteVersionId、ReleasedAt/By、CommandId；追加且不可改 |
| 终点事实 | ProducedAt/ProducedQty 缺少可核验加工依据 | 拟增 `WaferCompletion`：WaferId 唯一、WorkOrderId、LotIdAtCompletion、ProcessRunId、RouteVersionId、RouteStepId、CompletedAt/By、CommandId；由 F5 写入，禁止无 Run 的人工补值 |
| 工单基线 | Lot.SnapshotVersion 可空且未约束快照归属 | 正常生产 Lot 必须绑定有效 WorkOrderSnapshot 复合键；校验产品/路线对应快照 |
| 等待位置继承 | 无新旧 StepExecution 的显式关联 | 拟增 `StepExecutionInheritance`：GenealogyEventId、SourceStepExecutionId、TargetStepExecutionId，三者组合唯一；与血缘同事务写入 |
| 载具规格 | 现有类型与容量不表达晶圆尺寸 | 拟增 AllowedWaferSizeMm 正值；应用校验尺寸兼容，旧载具未补规格时禁止新装载 |
| 终态收尾 | CompletedAt 无法表达取消/转移/全报废 | Lot 拟增 ClosedAt、CloseReason；完成与其它终结分别约束 |
| 历史与范围 | 部分关系仅有普通外键 | 加固跨厂/工单一致性、状态转换、不可变归属身份；归属/装载仅允许合法一次关闭，已关闭区间不可改删；CarrierMovement 追加保护 |
| 共享可靠性 | 回执存在，未完整覆盖新用例 | 规范化摘要、对象范围重验、多对象版本、原子提交；按动作写审计与业务事件 |
| 运行权限 | 当前未开放 F4 表写入 | 增量授权最少表操作；同步 provision、能力权限目录、管理员初始化及回归，不扩大为全库写权限 |

迁移前只读盘点已有 Lot/Wafer。只有历史归属全部能唯一证明同工单/同厂时才可回填；首次投放/完成必须有可信事实。不能用当前 Lot 或 CreatedAt 猜造历史。遇到空工单、跨工单、缺失 Run 等存量，输出待处理清单并阻止相应强约束上线；不得删除数据凑通过。迁移、回填、字典/SQL 导出和回滚演练留待代码阶段。

## 11. 页面与交付门槛

| 页面/流程 | 展示和交互 |
| --- | --- |
| Lot 列表与建批 | 按工单/编号/状态/步骤/Hold 筛选；展示当前片数与在制量的不同口径；工单选择后展示固定基线及逐片表格 |
| Lot 详情 | 概览、片清单、当前等待/Run、Hold/阻塞、载具位置、血缘、事件与审计；未知依赖显式提示 |
| 投放 | 展示绑定版本、片数、额度及阻塞原因；确认后提交预期版本，不允许手工选起始步骤 |
| 拆批/合批 | 选择明确片集或完整源批；预览迁移前后数量及位置，显示全部不兼容原因；预览不占号、不锁资源，提交重验 |
| Wafer 履历 | 永久身份、来源、稳定工单、当前/历史 Lot、载具区间、逐片加工来源；不根据当前 Lot 推演旧历史 |
| 载具详情 | 槽位面板和表格双视图，扫码仅定位对象；装卸/交换前显示原槽及目标；移位单独留原因 |

查询统一处理加载、空数据、失败、无权限和缺失依赖。动作超时使用原键重试；412/409 需刷新并让用户重新核对，不自动选择新片集。提交成功刷新受影响 Lot、Wafer、Carrier、工单及血缘缓存；现阶段 HTTP 刷新足够，SignalR 不是 F4 的前置条件。

实施建议分为：数据归属/约束与公共事务 → 建批/查询/取消 → 载具 → 投放/等待步骤 → 拆合批/血缘 → F5/F6 联调终点与质量收尾 → F3 GAP-01 回补。F4 自身验收与跨模块验收分开记录；F5 未接通时不能把 F4-06 标完整实现。

F4/F5 完成后必须返回 F3，验证按唯一 Wafer 汇总、拆合批不重复投产、工单关闭与投放竞争以及缓存重算。F2 执行绑定同步核对 GAP-06。Docker 继续后置；Agent、真机、搬运、跨工单及复杂返工保持预留。具体迁移、代码开发和现场策略收敛在后续授权任务中推进。
