# F14-`DockerDeliveryAcceptance` Docker 交付与验收

更新：2026-11-18。用户确认先交付现有 F1～F12，F13 完成后补跑 Agent 专项。本轮覆盖 F14-01～03 的现有 MES 能力，F14-04 按试点目标另行确定。

## F14-01 单机交付

| 组件 | 职责 |
| --- | --- |
| `web` | Nginx 提供 React 静态资源，同源转发 API、SignalR 和健康检查。默认发布到宿主回环地址。正式入口由宿主 HTTPS 代理终止 TLS，保留外部 Host 和 WebSocket 升级。 |
| `api` | 非 root 运行现有模块化单体及 F12 Outbox Worker。复用授权、业务事务、会话和就绪检查。 |
| `postgres` | PostgreSQL 18.6，内部网络访问，使用独立命名卷。 |
| `migrate`、`provision`、`key-init` | 一次性任务。迁移完成后设置现有模块所需的运行权限，初始化 API 密钥与 PDF 卷权限。 |
| `bootstrap` | 运维显式建立首个管理员，沿用 F1 首登改密和重复引导保护。 |

交付 Compose 使用独立项目名和网络，现有数据库开发 Compose 继续作为本地开发入口。基础镜像使用固定摘要，NuGet 和 npm 依赖按锁文件还原。API 只得到运行角色凭据，引导、迁移、备份使用独立的运维入口。凭据文件存于 Git 忽略的实例目录。API 密钥和工艺 PDF 各有独立卷。Web 健康检查同时验证静态入口和上游就绪，API 探测用既有存活、就绪路由。无新增业务接口、页面或迁移。

## F14-02 演示和初始化

交付脚本支持建立空实例、启动服务和显式创建管理员。演示命令在全新的实例中复用浏览器验收流程，经实际 API 和 WebUI 生成虚构账号、工艺、设备、工单和 Lot。包含五片三站完工、拆合批和追溯，以及为浏览器验收准备的两项历史/投递样本。每次以新实例重建，数据与实际实例隔离。

## F14-03 备份、恢复和验收

备份时暂停 Web 和 API（含 Worker）写入，以同一停写窗口归档数据库、PDF 和 Data Protection 密钥。备份清单记录厂区标识和三个文件的 SHA-256。数据库逻辑备份去除宿主角色和授权，恢复后由部署脚本重建运行授权。备份目标必须为新目录，完成后才生成清单。

恢复先检查清单，再建立空目标实例，写入数据库与两个文件卷，沿用原 Fab ID。恢复到新实例也用于迁移后的回退演练，回切前核对旧版本兼容性和备份时间。备份含敏感业务数据及会话密钥，部署方保管加密副本并复制到独立存储。数据卷和备份卷归属均由运维脚本显式定位。

| 验收 | 通过条件 |
| --- | --- |
| 空环境启动 | 镜像构建成功，迁移和授权任务退出成功；Web、API 和数据库就绪。 |
| 事务与权限 | 隔离 PostgreSQL 上运行数据库和 API 回归；浏览器以运行角色完成 F1～F12 路径和越权、撤权检查。 |
| 容器重建 | 原会话可用，完工数量、追溯事件、PDF 的字节保持一致。 |
| 数据库故障与恢复 | 停库期间就绪失败，再启动后同源 API 恢复就绪。 |
| 备份恢复 | 独立新实例中原会话 Cookie、权限、工单进度、追溯事件和 PDF 摘要核对通过。 |
| Agent | 待 F13 完成后补跑工具、授权、引用和故障降级。 |

交付命令和环境要求见 [部署操作](../../deploy/README.md)。容量、留存、可用性、RPO/RTO、多节点恢复和真实外部接口验收归 F14-04。
