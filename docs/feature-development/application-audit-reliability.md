## 事务与投递

F2/F3～F7、F10 和 F11 的工作台刷新沿用现有影响范围。共享应用入口在成功且产生相关审计的命令中加入一条 `WorkbenchRefreshRequested` 业务事件及对应 Outbox。预览、失败和幂等重放均跳过。事件只含契约版本及刷新来源，持有服务端生成的事件 ID、厂区和追踪 ID。原生领域事件和审计仍由所属模块编写。

后台 Worker 轮询部署厂区的到期消息。每次以 `FOR UPDATE SKIP LOCKED` 在短事务内领取一行，调用本地刷新处理器，再提交投递状态。持锁期间只做数据库与进程内操作。进程退出或数据库连接断开时锁随事务释放，消息可重新领取。成功状态本身就是持久消费标记。发送成功后若提交结果未知，进程内按事件 ID 合并近期重复提示。跨进程恢复仍按至少一次处理，提示只触发幂等的 GET，SignalR 连接重建和定期刷新继续取快照。

失败记安全错误码，按 5、10、20、40 秒退避，连续 5 次失败进入死信。死信一直可查。重放要求独立权限、当前 ETag 和 1～500 字的原因，只能从死信状态重新排队，重置本轮尝试次数并追加审计。消息及原业务事件 ID 保持稳定，重放只调用刷新处理器。

SignalR 沿用每次发送前的会话、厂区及来源许可重查。客户端只收到刷新提示。首版采用单 API 实例，每实例的轮询使用数据库行锁防止并行消费。容量、跨实例即时广播和外部投递契约另行确认。

## 审计与权限

业务审计要求 `audit.operations.read`、部署厂区范围和来源模块读权限。系统在 SQL 中先过滤授权厂区与来源，再执行计数、排序和分页。工单导入继续仅对该任务提交者开放。原「操作审计」「安全事件」沿用 `security.audit.read` 与原入口。队列及积压要求管理员和 `security.outbox.read`，执行重放另需 `security.outbox.replay`。初始只给受保护系统管理员角色增加新权限。

新业务审计保存厂区和来源模块。历史操作审计保留原入口。业务审计按可核验的原记录厂区与来源读取历史事实。实例共享的工艺数据沿用 F2 单厂授权。来源无法可靠识别的历史行继续保存在数据库。前后值按业务记录可用内容呈现，凭据、内部存储位置及原始报文等字段在展示前剔除。队列只展示投递元数据和安全错误码。

## API 与运行状态

| 入口 | 行为 |
| --- | --- |
| `GET /api/v1/reliability/audit-logs` | 默认最近 7 天，跨度最多 90 天。支持 `from`、`to`、`actorId`、`entityType`、`entityId`、`action`、`sourceChannel`、`correlationId`，以及 `page`、`pageSize`。时间区间左闭右开，按发生时间倒序并按 ID 稳定排序。 |
| `GET /api/v1/reliability/outbox` | 分页查 `Pending`、`Published` 或 `DeadLettered`，支持用追踪 ID 定位。每条记录含 ETag。 |
| `POST /api/v1/reliability/outbox/{id}/replay` | 受防伪令牌、`If-Match`、厂区和权限保护，提交 `{ "reason": "..." }`，成功返回最新投递状态。 |
| `GET /api/v1/reliability/status` | 返回待发、死信、已投递数量及最早待发时间。 |
| `GET /health/live`、`GET /health/ready` | 进程存活与 PostgreSQL/队列表就绪。依赖未就绪返回 503，对外只提供状态。 |

请求日志和运行指标使用方法、路由模板、状态和耗时，错误与日志以追踪 ID 关联。投递指标记录成功、待重试和死信。审计排查从错误里的追踪 ID 进入。操作审计与业务史保持追加，原始事实的更正仍由各业务用例按权限追加。

Worker 默认启用。隔离环境可设 `Reliability__OutboxEnabled=false` 验证积压与恢复，命令仍写入 Outbox。监测可订阅 `MESagent.Api` 的 `mes.api.request.duration` 和 `MESagent.Outbox` 的 `mes.outbox.attempts`。队列状态从「组织与系统 → 审计与安全 → 事件投递」查看。

## 验收

- 同一成功命令的业务、审计、回执、业务事件和 Outbox 可用追踪 ID 核对。模拟失败或并发拒绝后相应事实全部回滚，响应丢失后同键重试只有一条消息。
- 关闭 Worker 后可见待发，恢复后完成投递。验证双消费者并发、暂时失败退避、五次失败死信、拒绝跨厂查询及越权重放、重放追加审计、重复消费对事实无副作用。
- 按对象、操作者、来源与追踪 ID 查审计，验证权限撤销、厂区隔离、来源权限、总数与分页和脱敏。
- WebUI 验证三个入口的角色显隐、死信重放、日志关联与工作台刷新。验证存活和依赖不可用时的就绪响应。
