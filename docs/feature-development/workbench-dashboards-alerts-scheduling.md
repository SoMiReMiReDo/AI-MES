## 工作台与生产总览

- 首页复用主导航路由和权限，按角色显示最多六个已授权快捷入口，菜单搜索覆盖全部已授权链接。生产卡片按权限显示。来源读权限和部署厂区共同约束统计、筛选项、下钻和实时订阅。
- 总览支持区域、工序和设备组筛选。WIP 为 Ready、Running、AwaitingDisposition 的已投放批次及其有效归属的 Active 晶圆。待加工为当前 Waiting 到访，Hold 按有效 Hold 去重计 Lot。实际运行查未结束 Run。设备取开放状态区间，缺区间显示未知。今日完工按厂区当天的终点完工事实计片。
- 区域、设备组从实际 Run 设备取得，等待时沿已指派设备。应用相关筛选时，无已知设备归属的批次不匹配。选工序时设备指标按已发布配方适用关系筛选。下钻沿用同一查询口径。

## 待办和站内告警

- 待办读取未解决 Issue、有效 Hold、等待处置 Lot 和未结束 Downtime，追随来源状态。提供原记录标识和下钻。
- 用户按来源启用个人订阅，生效后新出现的有效待办进入站内通知。待办保留打开的存量。个人通知可确认或静默到指定时间，静默期间暂停该条的超时升级。
- 每个来源可设置超时分钟以及本厂获来源读权限的升级收件人。原订阅用户和收件人都须处于启用和授权状态。超时仍有效、未确认且未静默的来源在收件人站内显示。相同来源对同一收件人合并。确认仅记录个人已读，原业务状态由来源模块处理。
- SignalR 只发送事务提交后的刷新提示，连接和发送前校验会话、厂区及来源权限。重连立即重查，每 15 秒复核连接并刷新到期静默和升级。授权或会话失效时关闭连接。HTTP 快照提供数据。

## 历史趋势和班次监控

- 趋势按厂区自然日，查询起止日均包含，单次最多 31 日。可筛选产品、工序、设备与班次。选择班次后，跨午夜事件归到班次开始日，产线班次只纳入可关联该产线设备的记录。通过片次按逐片 Run Passed 结果，终点完工按 WaferCompletion，报废按逐片 Scrap 处置，不合格分别列出 Run Failed 片次与未通过检验次数。等待为进入步骤到该到访首次 Track-in，周期为首次投放到终点完工。平均值缺失时留空。设备归属缺失的处置和检验在指定设备过滤时不计入。
- 班次按厂区时区和 ISO 星期展开，跨午夜归班次开始日，全厂或按产线匹配。进行中的班次按当前时刻截断。设备理想秒/片按生效日留存历史。
- 可用率 = 班内实际 Run 时间并集 ÷ 班内计划时长。性能 = 理想秒/片 × 加工量 ÷ 班内实际 Run 时间。质量率 = Passed ÷ (Passed + Failed)。OEE 为三项乘积。跨班次完成 Run 按时间重叠比例分摊逐片结果。缺班次、产速或完整逐片结果时相应项留空。性能保留原值。损失独立列出非运行时间、登记停机时间、可核算的性能损失和不合格量。等待批数和最早入队时间用于呈现当前瓶颈。

## 有限产能排程

- 支持新增、拖拽改时段与设备、编辑和取消。管理需要专门权限及执行、设备读权限。保存检查已下达工单、当前等待步骤、F5 批次门禁及冻结的设备/配方适用关系。已指派步骤只排向指派设备。
- 每个待加工到访最多一条有效计划，设备区间禁止重叠。时间采用左闭右开，必须落在适用班次内。未结维护从计划起点阻塞，周期维护从到期时刻阻塞。未结束加工或设备不可用时不估算恢复时间。工序因实际开工、拆合批或离开等待失效后，旧计划保留历史。
- 自动排程按优先级降序、等待时间及稳定 ID 排序。按有效理想秒/片 × 在制片数估算占用时长，选择最早可行时段和设备，并返回未排原因。共用全局事务写锁。编辑和取消使用 ETag，变更与审计一起提交。实际开工继续走 F5。自动排程最多尝试 50 批，搜索范围为 14 个厂区自然日，同一请求以 UUID 幂等键重放。

## 数据、接口与验收

沿用 MesDbContext、同源 Cookie、F1 授权与一致性快照。新增 `workbench` 下的设备产速、排程计划块、个人订阅和回执。增补排程与速率配置权限，系统管理员可分配。站内提醒根据已提交的源事实和个人设置计算。

| /api/v1/workbench | 操作 |
| --- | --- |
| GET /overview、/options、/records | 总览、授权筛选项、指标分页明细 |
| GET /history、/shifts | 按日趋势、班次 OEE 和损失 |
| POST /rates | 追加设备产速记录 |
| GET/POST /schedule、PUT /schedule/{id}、POST /schedule/{id}/cancel | 日历、计划新增、移动和取消 |
| POST /schedule/auto | 自动生成有限容量计划 |
| GET /schedule/{id}/history | 读取计划新增、移动与取消记录 |
| GET /alerts、/subscriptions | 来源待办、站内通知及个人订阅 |
| PUT /subscriptions/{kind}、PUT /alerts/{kind}/{id} | 保存个人订阅和告警回执 |
| /live | 同源 SignalR 连接，订阅 `Watch` |

`overview` 和 `records` 接受 `areaId`、`operationId` 和 `equipmentGroupId`。趋势查询用 `from`、`to`、`productId`、`operationId`、`equipmentId`、`shiftId`，趋势下钻使用 `kind` 和单日 `date`。列表分页默认 20，最大 100。班次监控最多查 7 日。

WIP 与终点完工需要 `production.lots.read`。待加工、Run 和逐片通过与失败需要 `execution.read`。Hold、报废和检验需要 `quality.read`，设备台账状态和停机需要 `equipment.read`。排程与班次监控同时检查执行和设备读权限。排程写入额外需要 `workbench.schedule.manage`，理想产速登记需要 `equipment.read` 与 `workbench.oee.configure`。

验收覆盖权限隔离、卡片与来源下钻、WIP 守恒、片次与完工区分、厂区日界、夜班和缺失口径、排程冲突和版本保护、实时重连、个人确认静默以及超时升级。
