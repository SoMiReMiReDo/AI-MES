# F6-`QualityExceptionDisposition` 质量、异常与处置

更新：2026-11-17｜状态：用户已确认首版范围，本文为实现基线，执行证据另见实现记录。

## 1. 范围与确认

用户确认完成 F6-01～04 的功能文档、后端、WebUI 与测试，并接通 F3/F4/F5：

| 功能 | 首版交付 |
| --- | --- |
| F6-01 | 原因码、异常类型；异常登记、确认、指派、处置、关闭；整改任务完成与复核 |
| F6-02 | Lot 多条 Hold、逐条解除、独立质量放行；等待处置的继续或当前站重试 |
| F6-03 | 检验模板、规格版本、发布冻结；Lot/逐片量测、样点、单位、设备和服务端判定 |
| F6-04 | 授权逐片报废，事务内关闭归属与载具占用，更新批次及工单查询 |

检验不合格自动建立异常与 Lot Hold。已通过但被 Hold 阻塞的加工，经审核继续；Failed/中止经授权创建当前站新到访重试，保留原加工事实。跨路线返工、自动质检任务、来料检验、单片 Hold、偏差审批、SPC/FDC/APC 与 Docker 保持后置。

## 2. 架构与职责

沿用模块化单体、单 MesDbContext、认证应用入口和事务内全局写锁。新增 `QualityExceptionDisposition` 模块，不引入新基础设施或依赖版本。Application 定义类型化请求，Domain 定义纯状态/检验规则，Infrastructure 的 `QualityBackend` 执行用例，API 仅映射协议，React 提供质量工作台。

质量模块拥有异常、Hold、检验、报废与质量放行事实；ExecutionBackend 拥有恢复后的步骤推进和新到访；ProductionBackend 拥有逐片归属、载具收尾及终点完成。所有协作在原请求事务中完成，失败时业务、审计、业务事件及幂等回执全部回滚。Agent 将来复用同一服务端入口。

普通查询使用现有一致性快照。写操作重载权限及厂区范围，执行对象授权、幂等、If-Match、状态规则后提交。质量操作不要求操作者额外获得执行/生产权限；内部协作必须验证本次质量授权和放行凭据。

## 3. 数据与厂区

复用现有 quality 表。异常至少关联工单、Lot、Wafer 或设备之一，步骤必须关联 Lot。所有关联对象分别验证部署厂区及相互一致；Lot 推导工单，Wafer 验证当前 Lot 成员，步骤验证所属 Lot，设备沿 Area 解析厂区。责任人须为启用的人类账号并具备本厂范围。只读历史通过来源对象解析范围，孤立或来源不明的旧记录不开放。

异常类型、原因码、规格与模板属于单厂实例共享配置，仍需本厂范围。原因码类别为 `Hold`、`Scrap`、`Disposition`，使用时要求类别正确且启用；停用保留历史。异常阻塞属性在登记时冻结，避免更改类型影响已有异常。

补充模板的 Draft/Released 生命周期和发布人/时间；模板参数绑定具体规格版本，发布后不可改，复制新版本。规格支持 decimal/integer、boolean、string；数值保存上下限，布尔/文本保存期望值。发布规格不可变。检验记录关联自动异常；质量放行补充恢复动作、原步骤/Run 和命令标识，持久保存恢复凭据。

## 4. 异常与整改

异常状态：`Open → Acknowledged → Resolved → Closed`。确认后可指派本厂责任人；处置须填写结论、原因、遏制措施及说明，结论为 Continue/Retry/Scrap。处置结论不直接修改加工、报废或 Hold。需要生产动作时另外执行明确命令。

整改状态：`Open → Completed → Verified`，保存执行/复核人与时间。关闭异常前须已处置、全部整改复核、关联 Hold 已解除。任何阶段不得覆盖已结束加工、已录入量测或报废事实。阻塞异常登记时原子创建 Hold（要求有效 Hold 原因码）；自动检验异常使用系统保留类型和原因码。

## 5. Hold、质量放行与恢复

Hold 是独立记录，不覆盖 Lot 生产状态。允许对 Draft/Ready/Running/AwaitingDisposition 添加；终结 Lot 拒绝新增。Running 新增 Hold 允许 F5 受控收尾，禁止新加工。多条 Hold 必须逐条解除；关联异常须先完成处置，解除最后一条也不自动推进。

质量放行要求无剩余 Hold、停工、未完成质量任务和未处置阻塞异常，工单仍为 Released。`None` 仅记录质量审核，不改变当前步骤；Ready/Draft 仅允许此动作。`Continue` 仅适用于 AwaitingDisposition、已结束且 Completed 的当前 Run，所有仍有效的晶圆均有 Passed 结果，必填作业已完成；报废片有可信处置事实时可从当前参与集合扣除。通过原路线的下一站或调用 F4 真实终点；不得跳站。

`Retry` 仅适用于 AwaitingDisposition、已结束的 Failed/Aborted 加工。关闭旧到访并创建同 RouteStep 的 VisitNo+1，重新记录点检、输出、指导书确认和 Run；不继承本次失败的作业记录。重试仍由 F5 校验设备和 Recipe，放行不会启动设备。解除 Hold、异常关闭和质量放行为三个独立动作。

## 6. 检验

模板绑定路线版本及可选步骤、样本数和具体规格版本；发布校验规格均 Released。首版手工发起检验，不启动 F6-05 自动任务。模板可独立于已发布路线创建新版本，不修改路线或工单既有基线；每次检验明确选择已发布模板。

一次提交必须包含每个样本及每个模板参数，唯一键为 Wafer/样本号/样点/规格；不接受客户端判定结果或规格限。Lot 模式 WaferId 均空；Wafer 模式按所选有效成员完整录入样本。数量、样本号、参数类型、单位及可选量测设备均由后端核验。数值判定采用闭区间，单边限有效；布尔/文本与发布规格期望值相等。精度限制为数据库 decimal(20,6)，拒绝隐式舍入。

保存量测时复制参数代码、类型、单位、上下限及绑定规格 ID；检验与量测不可修改。不合格在同一事务创建异常及 Hold，重复请求不重复创建。复检创建新记录，合格复检不自动解除旧 Hold；人工处置后放行，保留全部历史。

## 7. 报废与数量

仅对已投放且 Active、当前归属于指定 Lot 的晶圆报废；片集非空、唯一、最多100，声明数量必须与片集相等。Running 必须先由 F5 收尾；拒绝已完工、已取消、重复报废、跨厂/跨 Lot 片。允许有 Hold 或等待处置时进行报废，Hold 不因报废自动删除。

一次命令保存 ScrapEntry 及逐片 WaferDisposition（含原 Lot、步骤/Run、原因、执行/授权人），调用 F4 关闭有效 LotMembership 与 CarrierLoad。部分报废保留剩余片和工艺位置，全部报废关闭 Lot 为 AllScrapped，不能算完工。仍有 Passed 晶圆时经 Continue 继续，仍有 Failed 则 Retry。首次投放量不回减，不重复计数；`投放 = 在制 + 完工 + 报废`，工单关闭继续按真实片事实与阻塞门禁判断。

## 8. 权限与页面

权限分为 `quality.read`、`quality.configuration`、`quality.issues`、`quality.hold`、`quality.release`、`quality.inspect`、`quality.scrap`。新权限通过迁移加入权限目录和既有 SystemAdmin，其他角色由管理员明确授权，不覆盖已有配置。质量放行与报废不因“管理员”名称隐式获得权限。

WebUI 新增质量管理：异常与整改、Lot 冻结/放行/恢复、检验记录与录入、逐片报废、质量配置。列表分页、筛选、空/错状态、详情及版本冲突沿用现有组件；业务编号和中文状态可辨。提交前显示对象、原因、片集和动作，失败保留输入；所有权限仍在服务端复核。
