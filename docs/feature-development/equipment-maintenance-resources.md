更新：2026-11-17｜状态：用户已确认 F7-01～07 范围及细化规则；代码已集成并通过本地验收，结果见实现记录。

| 功能 | 本轮交付 |
| --- | --- |
| F7-01 | 类型/组维护、设备区域/产线与启用管理、能力及当前 Lot/Run、腔体台账 |
| F7-02 | 人工/模拟状态与通信事件、来源去重、乱序拒绝留痕、有效状态区间、当前加工与故障影响 |
| F7-03 | 停机登记、原因补录、未分类清单、时间窗口及设备/原因/班次时长统计 |
| F7-04 | 工具台账、设备绑定、小时/天周期计划、维护工单、延期、开始/完成/独立复机及派工门禁 |
| F7-05 | 设备/人员工序及可选 Recipe 资格、生效/过期/撤销、复认证记录、按工序启用门禁 |
| F7-06 | 光罩版本/层次、装卸区间、寿命、实际 Run 关联和受影响 Lot/Wafer |

用户已确认：加工中故障只记录 Down 并阻止新加工；保留当前 Run，由操作员按 F5 收尾、F6 处置。不会因设备事件覆盖 Run 结果或自动删除设备占用。Docker 继续后置。

用户已确认细化方案：资格按工序启用、光罩按启动 Run 次数计寿命、耗材按时间寿命且不扣库存、到期维护阻止启动及完成后独立复机。本轮按该基线实施。

## 2. 实现架构

延续模块化单体、单 MesDbContext、同源 WebUI 以及统一认证应用入口。新增 `EquipmentMaintenanceResources` 模块，代码使用英文能力名；保留 `/equipment/tools` 作为物理设备的既有接口，实际工具使用 `/equipment/resources`，避免改变 F5 调用。

| 层/模块 | 职责 |
| --- | --- |
| Application | 类型化台账、事件、维护、资格和装卸命令；设备模块接口 |
| Domain | 设备资源实体与纯寿命/状态规则，不依赖 EF/HTTP |
| EquipmentBackend | 设备业务入口、范围与版本验证、审计及幂等回执 |
| EquipmentResources | 同进程共享可加工性检查、状态区间维护、Run 资源事实记录 |
| ExecutionBackend | 继续拥有派工、Track-in/out、Run 和片集；调用设备共享能力 |
| QualityBackend | 继续拥有质量处置与恢复；设备状态恢复不替代质量放行 |
| React | 设备与资源工作台、停机、维护、资格/门禁、光罩、耗材与影响查询 |

每条写命令仍由统一入口重载权限、解析部署厂区并取得既有全局事务写锁。业务变化、区间、资源关联、审计、业务事件与回执原子提交。不同模块不得各自提交，或通过 HTTP 调用制造半成功结果。只读采用现有一致性快照。Agent 将来只能调用同一应用规则。

## 3. 身份、范围与历史

设备沿 Area 和 EquipmentGroup 双重校验厂区；产线必须属于所选 Area。设备组属于厂区；类型、工序、Recipe 属于单厂实例共享配置，仍要求部署厂区授权。腔体、状态、事件、维护、装卸沿设备解析范围。工具与光罩新增明确 FabId；来源不明的旧资源不推断厂区、不开放使用。人员资格必须关联本厂 Worker，账号权限不能替代人员工艺资格。

物料批通过 Warehouse 解析厂区；本轮最小耗材登记使用本厂明确标识的登记仓，不伪造完整采购/收货/库存事实。QuantityReceived/Available 为零，不提供库存可用量承诺，后续 F8 另行建立库存账本。既有物料仅在厂区、单位、状态、有效期和冻结校验通过后上机。

业务编码创建后不修改。设备已有工艺/加工关联后，其类型与组织归属冻结；可修改名称、说明和启用状态，停用不删除历史。加工中禁止搬迁、停用及资源装卸。设备故障事件仍可登记。腔体只提供台账，本轮单设备单 Lot 的执行规则保持；腔体级调度与共炉见 GAP-14。

## 4. 运行、通信及事件

`OperationalState` 为人工/模拟运行条件：Idle、Down、Maintenance、Offline。当前加工由 Running 的 ProcessRun 确认。有效状态优先使用非 Idle 的设备条件；条件为 Idle 且有 Running Run 时显示 Running，否则 Idle。Track-in/out 与中止调用共享区间维护，单设备任意时刻至多一个开放区间，区间采用左闭右开边界。

通信状态为 Unknown/Online/Offline，单独保存，不据此创建加工或宣称设备可用。可启动还需启用、有效组织/类型、无占用、工艺/Recipe 匹配及所有已启用的维护/资格/资源门禁。

人工状态变更必须填写原因并提交 If-Match。模拟入口只接受显式 Simulator 来源标识，记录事件发生时间、接收时间和来源事件编号；不连接真实设备。来源编号按设备/来源唯一，同编号同内容重放，异内容冲突。过旧/同一时点和无效转换保留 Rejected 事件及原因，不覆盖当前状态；未来时间和不合法请求拒绝。状态区间以接收并应用时刻推进，发生时间仅用于顺序判断，避免回写既有区间。

Down 时当前 Run 保留。恢复 Idle 只改变设备条件，已有 Running Run 的有效状态仍为 Running。操作者完成或中止后按 F5/F6 判定生产后续行为。

## 5. 停机与统计

Down 区间是停机时长的唯一时间来源。进入 Down 原子建立 Downtime，退出时同步关闭；一个区间只允许一个停机记录。维护和 Offline 分列，不混算故障停机或 OEE。

可以为历史未登记的 Down 区间补登记；不提供自由填写时间、与已记录区间重复计量的入口。原因允许暂缺，形成未分类待办；补分类需 Downtime 版本、启用的 Downtime 原因、说明及可选本厂班次，保留审计。班次为显式归类，未填时统计为“未指定”，不推断排班或补成自动跨班拆分。

统计区间默认最近30天，最多366天；每个状态区间裁剪到查询窗口，开放区间截止本次 asOf。先按厂区/设备过滤，再汇总。设备、原因、班次统计都由同一批状态事实生成，不加总重复 Downtime 时间。较早无绑定停机的 Down 区间仍计停机，原因/班次为空。当前视图只表示查询时点的统计。

## 6. 维护与复机

工具独立台账，可绑定设备；工具编码固定；绑定设备可在双方无加工且工具无未关闭维护时调整或解除，变更保留审计。维护计划目标为设备或工具，二者恰选一；维护事件引用计划时继承并验证目标，不接受不一致目标。计划支持 Hours/Days 正整数周期、负责人、下次到期时间与启用状态；负责人必须为本厂启用的人类账号。

确认规则：有效计划到期、设备工具本身不可用、已经到期的 Planned 工单、InProgress 或 Completed 待复机工单阻止新加工。未来 Planned 工单不提前阻塞。

状态流程为 Planned → InProgress → Completed → Released。开始维护前设备须无 Running Run；维护完成记录结论，仍保留门禁。具有独立 `equipment.release` 权限的用户确认复机；复机只释放此维护工单，不自动将 Down 改 Idle、不发放工艺资格。周期计划在复机时按实际确认时间计算下一到期点，避免完成但未复机时提前解除到期门禁。

计划延期和 Planned 工单延期均要求新时间、版本与原因，保留前后值的审计；不能通过延期终结已开始维护。计划停用须显式管理，不能解除已经创建的维护工单。工具不可用与维护工单是独立门禁。

## 7. 资格与门禁策略

按工序设置统一资格门禁，兼容已有工序默认关闭；启用后必须同时满足设备和当前操作员的人员资格，不允许只开启其中一项。配置启用后，派工候选、指派与 Track-in 共用判定。人员资格取当前用户绑定的 Worker，须启用且为本厂。资格以 Operation 为基础，可缩小到指定 Released RecipeVersion；有效区间为 `[ValidFrom, ValidTo)`，过期立即影响下一次启动。

新认证追加记录；撤销需资格版本与原因，保留原生效区间及审计。Recipe 专项资格存在时优先于通用资格；不得用通用资格绕过专项失效。门禁变更不改已完成或正在加工的事实，启动事务中重新校验，列表候选不构成承诺。

## 8. 光罩与耗材

光罩按 Code+Revision 唯一、保存 LayerCode、MaxUsageCount、UsableUntil。版本与层次创建后固定；停用、Blocked/Available 状态可维护。装卸有独立设备/光罩版本及区间，一台设备当前最多一个光罩，一个光罩同时只能在一台设备。

工序可以声明必需层次。启动时验证装载光罩启用、Available、层次匹配、时间有效且次数未耗尽；创建 ReticleUsage，UsageCount 在同一事务递增一次。中止保留已消耗次数，幂等重放不重复计数。卸下光罩不删除历史，影响查询通过 Usage → Run → ProcessRunWafer 获取当时晶圆，不以当前 Lot 成员替代。

耗材通过 Material/MaterialLot 最小登记与物料上机区间管理；上机保存开封时间和明确截止时点，截止不得晚于批次有效期。校验启用、厂区、单位、状态及有效 Hold，禁止加工中卸下/换料。同设备同物料当前最多一个有效批；工序可要求多个 Material。Track-in 校验必需物料已上机且仍有效，并保存所有实际在机耗材与 Run 的关联。

本轮按时间寿命校验，不推断每片精确消耗、不扣减库存、不伪造物料领用。影响查询的 coverage 表示已记录 Run 关联；启用前的历史不能据此声称完整覆盖。光罩/耗材到期不改写当前 Run，由操作员受控收尾；下一次启动拒绝。

## 11. 模型差异与兼容

| 模型 | 增量与用途 |
| --- | --- |
| Equipment | CommunicationState；与运行条件及 Run 占用独立 |
| EquipmentEvent | Source/SourceEventId、ProcessingStatus/RejectionReason；保留去重与乱序证据 |
| Downtime | EquipmentStateId 唯一关联；状态区间是权威时间源 |
| Tool / Reticle | 明确 FabId；旧记录厂区为空时不猜测、不开放使用 |
| Tool / MaintenanceEvent | 工具设备绑定；维护 ReleasedAt/ReleasedById 独立复机事实 |
| EquipmentOperationPolicy | 按工序统一资格门禁及必需光罩层次；独立运行准入配置 |
| EquipmentMaterialRequirement | 工序与必需耗材的显式关系；策略修改有审计，不改实际使用历史 |
| ReticleMount / ReticleUsage | 设备装卸区间、Run 实际使用；光罩限次与有效截止 |
| MaterialLot / MaterialMount | ResourceExpiryAt 精确截止；上机 MaterialId 用于设备同物料互斥 |
| MaterialRunUsage | 每次实际 Run 使用的上机记录，唯一关联与追加历史保护 |

本轮新增4张关联/策略表，原表仅增量扩展。已执行和正在执行的 Run 不回填虚构资源使用；迁移只从启用时点开始校准现有 Running 设备的有效状态，不重建早期加工状态时长。旧数据来源不明时明确标缺。材料批次只有日期有效期时，按厂区时区该日期的次日零点作为上界；精确有效截止存在时取更早者。单位必须与定义一致，不隐式换算。

最小运行授权单独增量执行：不改密码，不授予 DDL 或生产/资源历史 DELETE；仅工序耗材要求这类可编辑配置需要删除关系权限。完整采购、收发存、精确耗用、自动班次拆分、腔体调度/共炉与实机联接另列扩展，不属于本轮已实现声明。
