## 2. 能力规则

| 功能 | 本轮设计与规则 |
| --- | --- |
| F2-01 产品与修订 | 产品编码唯一，维护名称、单位、分类和启用状态。修订归属产品，修订号在产品内唯一；发布必须绑定有效的已发布路线版本。支持按修订查询受影响工单与 Lot，结果受厂区权限限制。 |
| F2-02 路线与步骤 | 工序可重复出现，以 RouteStepId 区分。路线版本至少一个步骤，顺序号为正且版本内唯一；允许不连续。步骤绑定有效工序，可配置设备类型和指导信息；发布后步骤、点检、输出定义不可编辑。复制版本时重新生成步骤 ID，并显式复制子定义。 |
| F2-03 Recipe | Recipe 下维护唯一版本号、参数和校验摘要；适用关系绑定具体版本、步骤和设备，有效期采用左闭右开区间。候选查询同时校验版本发布状态、适用区间、步骤及设备匹配；实际采用版本的记录由 F5 回补。禁止把候选查询视为设备加工许可。 |
| F2-04 编号 | 规则包含用途、可选产品、前后缀、位宽、下一序号；规则优先选择产品专用，再选用途默认。预览不消耗序号；正式分配以行锁和唯一约束防重，分配与业务创建同事务；同一幂等键重试返回原结果。允许断号，禁止回拨已使用区间。 |
| F2-05 步骤定义与文档 | 点检项含必填、排序；输出项的 key 在步骤内唯一，类型限定 string/decimal/integer/boolean/datetime/enum，枚举须有选项，单位可选。关联有版本及摘要的作业指导书，提供受权上传、下载和发布；执行数据采集归 F5。 |

编号首版采用固定前后缀加补零整数，Pattern 只接受该模板，ResetPeriod 仅支持 None；日期重置等扩展登记在待补全清单。此限制需在代码任务开始前与用户确认，不将现有可空字段推断为完整能力。

## 3. 生命周期与发布

统一版本状态：Draft → Released → Obsolete。只有 Draft 可改内容；Released 不可撤回草稿；Obsolete 不可重新发布。更新通过复制新版本完成，发布、废止均记操作者、时间、原因与审计。主数据停用不删除历史引用，但阻止新发布与新业务选择。

发布时间与有效期分开；带有效期的对象满足 from < to，空端点表示无界。产品发布时校验路线归属（若路线限定产品）、工序与关联定义完整性；工单下达时重新校验当时有效性。Recipe 适用关系变更必须审计并检查区间冲突，历史执行保留采用的版本与适用依据，不能随配置变化改写。

发布用事务锁定父版本并校验子项；编辑子项必须取得相同父级锁，避免发布与修改穿透。废止阻止新的使用，不自动修改已有工单基线或在制 Lot；受控切换见 F2-06。

## 4. 权限、存储与界面

新增建议权限：engineering.read/manage/release、engineering.numbers.allocate、engineering.documents.manage。SystemAdmin 配置授权，ProcessEngineer 建议承担编辑和发布；角色名称本身不授予权限。工程主数据当前无 FabId，按单厂部署范围授权，禁止宣称已支持多厂隔离；工单/Lot 影响查询按对象厂区过滤。

API 和未来 Agent 共用 Application 用例；Domain 定义状态规则，Infrastructure 实现 EF、事务、审计和附件存储。写入遵循 Cookie、防伪、会话、权限、xmin 并发校验。上传使用服务端生成路径、大小/类型白名单和摘要校验，不接收任意磁盘路径；下载必须重新授权。首版指导书建议限 PDF、10 MiB，具体配置在代码阶段确认。

WebUI：产品及修订页、路线版本/步骤编辑页、Recipe/适用性页、编号规则页；版本详情展示状态、发布信息、影响对象和只读原因，点检、输出及指导书在步骤详情维护。发布前展示校验结果与影响摘要。

## 5. 模型差异与实施准备

- RecipeVersion 没有自身有效期字段，当前有效期属于 RecipeApplicability；首版按适用关系判定，不虚构版本字段。
- RouteVersion/RecipeVersion 没有独立废止时间；首版由审计记录，若需实体字段再迁移。
- EngineeringDocument 使用多态 EntityType/EntityId，应用层需验证绑定对象、版本和范围；发布文档及文件不可覆盖，更新创建新修订。发布路线引用的文档绑定须冻结，存储与失败清理机制待实现。
- NumberSequence 缺少分配回执关联；代码阶段评估复用既有幂等存储，必要时迁移，避免仅靠计数器应对重试。
- 现有字符串状态字段不等于状态机；需应用校验，必要的约束迁移必须兼容既有数据。

实施顺序建议：权限与契约 → 主数据/草稿 → 发布与并发保护 → Recipe/编号/附件 → WebUI → 集成验收。代码开始前另行沟通并确认开发计划。
