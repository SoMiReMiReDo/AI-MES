1# Machine counter browser checks
2
3## Ready-to-use local demo
4
5Log in as an admin or supervisor and open:
6
7**http://localhost:8080/admin/connectivity/counters?counter=2**
8
9This session left that fresh demo at zero. Counter **1** contains the completed automated
10walkthrough and its audit history. These IDs belong to this development database only.
11The demo has its own line, product, order and two batches of **10 pieces each**, sharing one
12station. It does not connect to a PLC or broker. The page is also linked from
13**Connectivity → Overview → Machine counters** (Polish: **Połączenia → Przegląd → Liczniki maszyn**).
14
15For another fresh demo, run from the repository root on the local development installation:
16
17```sh
18docker exec openmmes-backend php artisan machine-counters:demo 1 --force
19```
20
21`1` is this installation's admin user ID. The command prints a new URL and never resets existing
22data. `--force` is needed because this local Docker instance uses `APP_ENV=production`; do not
23use this command against your production database. Simulation controls are restricted to these
24CLI-created test sources. Normal machine channels cannot enable simulation through the web UI.

26## Walkthrough
27
28Use **Raw count / Wartość surowa → Send test reading / Wyślij odczyt testowy**.
29Leave the event ID and timestamp empty until instructed otherwise. The simulator stamps the
30current acquisition time; real gateways must supply their acquisition timestamp.
31
32| Step | Browser action | Expected result |
33|---|---|---|
34| 1 | Send **1000**, then **1003**. | First reading establishes the baseline: **0** good. Second reading: batch 1 has **3** good. |
35| 2 | Send **1003** again. | Still **3** good; history says **Unchanged / Bez zmian**. |
36| 3 | Send **2**, then **1010**. | Both leave output at **3**. **Reset review required** remains active even after the raw count exceeds the old value. |
37| 4 | Enter a reset reason and click **Establish new baseline / Ustal nową wartość bazową**. Send **10**, then **12**. | 10 becomes the new baseline with no output. 12 adds 2: batch 1 now has **5** good. |
38| 5 | Select **Demo batch 2** under **Assigned batch step**, enter a reason, save configuration. Send **20**, then **22**. | Batch 2 starts at **0**, then reaches **2**. Batch 1 stays at **5**. |
39| 6 | Select **Unassigned / Nieprzypisane**, enter a reason, save. Send **30**, then **33**. | 30 is a baseline; the delta of **3** is retained as unassigned, with **0 applied**. Neither batch changes. |
40| 7 | On that unassigned row, click **Review / Przejrzyj**. Choose **Apply remaining good quantity**, select batch 2, enter a reason, save. | A separate **Reconciled / Uzgodniono** audit row applies **3** to batch 2. The original row retains its original attribution and cannot be reviewed twice. |
41| 8 | Assign the channel back to batch 2 and save with a reason. | Batch 2 shows **5** good. Assigning a channel does not replay old readings. |
42| 9 | Change mode to **Pulse / Impuls**, keep quality **Good**, save with a reason. Send **1** with an empty event ID. | Nothing counted; history says **Event ID required**. |
43| 10 | Send **1** with ID `manual-pulse-1`; repeat it; send **1** with ID `manual-pulse-2`. | Batch 2 progresses **6 → 6 → 7**. Reusing an event ID returns the existing reading; it creates no second production entry. |
44| 11 | Send 1 with a new ID and timestamp `2020-01-01T12:00:00Z`; then another new ID with `2099-01-01T12:00:00Z`. Clear the timestamp afterward. | Both are retained as out-of-order/future readings. Output stays at **7**. |
45| 12 | Change mode to **Increment / Przyrost**, save, send **5** with ID `manual-overflow`. | Batch 2 reaches its **10-piece** limit. History records delta **5**, applied **3**, status **Partially applied**. The remaining 2 require explicit review. |
46| 13 | Change to **Cumulative** and quality **Total (quality unknown)**, save, send **100**, then **103**. | No additional good output; the three unclassified pieces are retained for quality review. Repeat with quality **Reject**, values **0 → 2**: still no good output. |
47| 14 | Click **Awaiting review / Do weryfikacji**. Review a quality row and choose **Dismiss with reason**. | The row leaves the pending queue, and its reason remains in **All readings**. Total/reject readings cannot be silently converted into good output. |
48
49The current step's good count appears above its configuration. To inspect the other batch,
50select that batch in configuration and save with a reason. This establishes a new counting
51boundary, so subsequent cumulative readings need a fresh baseline.
52
53Try an unrelated workstation in configuration: saving must show a form error and preserve the
54existing assignment. At a mobile viewport, the forms must fit; the history table scrolls
55horizontally inside its own container.

57## Production-flow checks from the earlier changes
58
59On an isolated routed order with **Transfer** enabled under **Settings → System**:
60
611. Start the first step of a 10-piece batch; log **4 good + 1 scrap**.
622. The next station becomes ready with **4 incoming** while the first step is still running.
633. At the next step, attempting to log more than those 4 must fail. Log 2 good and check that
64 only 2 arrive downstream. Final order output comes only from the final effective step.
654. Attempt to finish the first step with 5 pieces still waiting: it must fail. Record the
66 remaining quantity before finishing. Downstream completion also waits for upstream closure.
675. Pause the order or open a blocking issue/QC task: output logging must stop.
686. Classify a generated scrap entry: the reason can change, but its quantity, step/order
69 association and deletion must remain protected.
707. Open two operator sessions on the same line. A valid quantity change must refresh the other
71 view; a session on another line must not receive that private line update.
72
73Do not change the global production-flow setting while real work is running.

85## Check upgrade compatibility
86
87Use a separate CLI-created demo for this check. Flow is a global setting: do this only on the
88isolated development instance, and restore its original value afterward.
89
901. In **Settings → System → Production**, select **Whole batch** and save.
912. Open the demo counter, expand **Return to legacy counting**, enter a reason and submit.
923. Reload the page. It must still say **Legacy counting is active** and offer **Enable explicit
93 counting**. Opening the page has not migrated the source.
944. Try enabling **Transfer** in system settings. Saving must fail with the incompatible tag ID.
955. Return to the counter, choose its workstation and **Demo batch 1**, enter a reason and click
96 **Enable explicit counting**. Send **1000 → 1003 → 1003**: good output must be **0 → 3 → 3**.
976. Enable Transfer again. With compatible channels and matching order/step totals, saving succeeds.
987. Attempt **Return to legacy counting** while Transfer is active: the form must reject it.
99
100Legacy MQTT payloads and Modbus/OPC UA readings without new event metadata are covered by backend
101integration tests. For real installations, keep existing publishers unchanged until their own
102channel is migrated. If a whole-batch machine order already has output that is not represented
103in its steps, finish or reconcile it before enabling Transfer; the settings gate reports it.
104
105Compatibility recording: `docs/review-evidence/counting-compatibility/compatibility.webm`.

107## Manual correction regression (Polish UI)
108
109Use a separate test order with counting source **Operator**, transfer flow, quantity 10,
110and at least two sequential steps. Enable **Korekty ilości produkcji → Pełna edycja**
111for this test and use the operator who started the step. Restore the previous policy afterward.
112Do not reuse live production work.
113
1141. Start the first step and log 4 good pieces. The next step receives 4.
1152. Expand **Skoryguj ilość dobrych sztuk**. Enter total 3 and a reason, then **Zapisz korektę**.
116 The first step shows 3 passed and 7 waiting; the next receives 3. The audit retains 4 → 3.
1173. Start the next step and log 2 good pieces. Try correcting the first total to 1.
118 An inline error must appear and both counts must remain unchanged.
1194. Correct the next total to 1 with a reason, then the first total to 1. Both are allowed.
1205. On the final step, a valid correction must also update the order's produced quantity.
1216. Check an old form after another session changes its total: submission must require refresh.
1227. Blank reasons, more than two decimals, machine-counted and completed steps are refused.
1238. In System settings, try switching to **Cała partia** with this order open: the switch must
124 fail and retain **Przekazywanie**. Finish/cancel test work when testing is complete.
