1# CLA — one-time setup (maintainer)
2
3The CLA gate is a GitHub Action (`.github/workflows/cla.yml`, "CLA Assistant"). It runs on every pull
4request, asks unsigned contributors to sign by commenting, records signatures in a **private** repo, and
5blocks merge until all commit authors have signed. Owner accounts, org members and bots are allow-listed.
6
7Do these steps once (GitHub web UI + a token). Order matters.
8
9## 1. Create the signatures repo
10
11Create a **private** repo **`Mes-Open/cla-signatures`** with an empty `README.md`. Signatures are stored
12here as `signatures/version1/cla.json` (created automatically on the first signature).
13
14## 2. Create a token and add it as a secret
15
16- Create a **fine-grained personal access token** scoped to **only** `Mes-Open/cla-signatures`, with
17 **Repository permissions → Contents: Read and write**.
18- In **`Mes-Open/OpenMes` → Settings → Secrets and variables → Actions**, add a secret named
19 **`CLA_SIGNATURES_PAT`** with that token.
20
21## 3. Allow the workflow to write
22
23**`Mes-Open/OpenMes` → Settings → Actions → General → Workflow permissions →** enable
24**"Read and write permissions"** (the action posts PR comments and updates the commit status).
25
26## 4. Require the check on the protected branch
27
28In branch protection for **`main`** (and, if PRs land there, **`develop`**), require the status check
29**`CLA Assistant`** to pass before merging.
30
31## 5. Publish CLA.md where the link points
32
33`cla.yml` points contributors to `https://github.com/Mes-Open/OpenMes/blob/main/CLA.md`. Make sure `CLA.md`
34is present on `main` (it ships to `main` at the next release). Until then, either merge `CLA.md` to `main`
35first or temporarily point `path-to-document` at the `develop` blob.
36
37## 6. Test it
38
39Open a test PR from an account **not** on the allowlist. Confirm: the bot comments asking for a signature →
40comment the sign phrase → the check turns green → a row appears in `Mes-Open/cla-signatures`
41(`signatures/version1/cla.json`).
42
43Also confirm the **CodeRabbit gate**: before signing, the PR has **no `cla-signed` label** and CodeRabbit
44does **not** auto-review; after signing, the workflow adds `cla-signed` and CodeRabbit reviews. (The label
45is created automatically the first time it is applied; you may pre-create a `cla-signed` label with a
46distinctive colour if you like.)
47
48## CodeRabbit ordering (sign first, then review)
49
50`.coderabbit.yaml` sets `reviews.auto_review.enabled: false` with `labels: [cla-signed]`, so CodeRabbit
51only auto-reviews PRs that carry the **`cla-signed`** label. `cla.yml` adds that label once the CLA step
52passes (all commit authors signed or allow-listed) and removes it if a later unsigned commit is pushed.
53Net effect: **contributors sign first, then CodeRabbit reviews** — no review budget spent on unsigned PRs.
54The hard merge block remains the required **`CLA Assistant`** status check (step 4); the label is only a
55review-timing convenience.

59## Tool note (accepted risk + alternative)
60
61`cla.yml` uses **`contributor-assistant/github-action`** (CLA Assistant Lite), **pinned to the exact commit
62of `v2.6.1`** (`ca4a40a…`). That repo was **archived in March 2026** — it is frozen, not broken; pinning to
63a SHA removes the moving-tag supply-chain risk, it runs only in CI, and it never ships in the product. Its
64advantage is that the **signature ledger stays inside `Mes-Open`** (your own private repo).
65
66If you prefer an actively-maintained tool, the alternative is the hosted **[cla-assistant.io](https://cla-assistant.io)**
67(SAP): a GitHub App, no workflow file or PAT to manage — but the signature data then lives on SAP's servers,
68not in your organization. Choose based on whether keeping the ledger in `Mes-Open` is a hard requirement.
69
70## Allowlist maintenance
71
72The allowlist in `cla.yml` covers only the owner's own accounts and bots:
73`jakub-przepiora`, `jakubprzepiora-cyber`, `dependabot[bot]`, `github-actions[bot]`, `renovate[bot]`.
74
75Org members (`Svannte` / Mateusz Łuczyński, `JanKolo04` / Jan Kołodziej, `ElNinio978`) are **intentionally
76not allow-listed** — they sign via the bot as well; their ICLA then operates on behalf of and with the
77company's consent (CLA §C4). Add or remove logins here as the team changes.
