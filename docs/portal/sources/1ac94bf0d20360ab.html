43<a id="installation"></a>
44## 安装
45
46> 第一次在工厂部署 OpenMES？本章讲的是软件本身。
47> [实施手册](implementation-runbook.md) 讲的是围绕它的整套流程——
48> 基础设施、配置顺序、主数据、试点、上线与交接。
49
50### 前置条件
51
52- Docker 20.10+ 与 Docker Compose
53- Git
54
55### 步骤
56
57```bash
58# 1. Clone the repository
59git clone https://github.com/Mes-Open/OpenMes.git
60cd OpenMes
61
62# 2. Start containers
63docker-compose up -d
64
65# 3. Open browser
66# Navigate to http://localhost
67```
68
69Web 安装向导会引导你完成三个步骤：
701. **基础配置** —— 站点名称、URL 以及**工厂时区**
712. **数据库配置** —— PostgreSQL 连接信息
723. **管理员账户** —— 你的管理员用户名、邮箱与密码
73
74完成向导后，系统即可使用。
75
76> **工厂时区。** 选择*工厂*所在的时区，而不是服务器的时区：每个
77> 时间戳、报表边界与班次切分都以它为准，一旦不一致，某天的报表覆盖的
78> 时段就会与实际工作的班次错开。向导会把它存进数据库，该值优先于
79> `APP_TIMEZONE`——在 Docker 上，环境变量来自 `docker-compose.yml`，
80> 无法从应用内部修改。
81
82### 生产部署
83
84生产环境请参见主 README 中的部署说明。请确保：
85- `.env` 中 `APP_DEBUG=false`
86- 已配置 HTTPS（使用 Caddy 或 Nginx 之类的反向代理）
87- `.env` 文件已妥善保护，且未提交到版本控制

93
94安装完成后，请完成以下清单：
95

994. **创建产品类型** —— 产品的分类
1005. **创建工艺模板** —— 每个产品的分步工作流
1016. **导入或创建工单** —— 待生产的工单
1027. **加载示例数据**（可选）—— Settings → Sample Data 会加载贴近真实的测试数据

108

112
113| 角色 | 权限 |
114|---|---|
115| `Admin` | 全系统权限：设置、全部数据、用户管理 |
116| `Supervisor` | 接受/拒绝工单、管理问题、查看报表 |

120

1244. 点击 **Save**
125
126### 分配产线
127
128操作员只能看到自己被分配的产线。分配产线：
1291. 打开用户资料页
1302. 在 **Lines** 区域从列表中选择产线
1313. 保存更改

196## 工单
197
198<a id="creating-orders-manually"></a>
199### 手动创建工单
200
2011. 前往 **Admin → Work Orders → New**
2022. 填写：
203 - **Order number**（唯一）
204 - **Product name**
205 - **Quantity**
206 - **Line**（产线）
207 - **Product type** 与 **Process template**
208 - **Due date** 与 **Priority**（1–5）
209 - 周/月/年编号（若已配置生产周期）
2103. 保存——工单以 **Pending** 状态创建
211
212主管必须先接受工单，操作员才能开始处理它。
213
214<a id="importing-data-admin--import"></a>
215### 导入数据（Admin → Import）
216
217一个导入器即可从表格加载主数据与工单——所有实体共用同一个界面，
218风格类似车间系统的导入页面：
219
2201. 前往 **Admin → Import**（主管：**Supervisor → Orders → Import**，仅限工单）。
221 该页面位于 Settings → Access 下独立的 `import` 标签页；升级之后只有
222 Admin 拥有它。
2232. 选择**要导入的内容**：产品类型、物料、工单或物料清单（BOM）。
224 右侧面板会列出该实体的**可用字段**（必填项带星号），并提供每个实体的
225 **示例 CSV**。
2263. 上传 `.csv`、`.txt`、`.xls` 或 `.xlsx` 文件（最大 32 MB）。CSV 可指定
227 **字段分隔符**（默认自动探测：`;`、`,` 或制表符）与**编码**
228 （UTF-8、ISO-8859-1、Windows-1250，用于较旧的波兰语导出文件）。
2294. 设置该实体的运行选项——**策略**（插入或更新 / 仅插入 /
230 仅更新 / 重复时报错），以及各实体的选项：外部系统与分类
231 筛选（产品类型、物料）、默认物料类型、目标产线与计划
232 周期（工单）、替换还是合并（配方）。
2335. **映射列**：文件中的每一列都分配到一个字段。列会从常见的
234 英文和波兰语表头自动识别；工单还接受 `custom:<key>` 目标，
235 它们会作为额外数据保留在工单上。映射可保存为**配置档案**并复用。
2366. **运行**：导入进入队列并在后台处理。运行页面显示实时进度条，完成后显示
237 逐行错误，含文件行号、字段与原因——可下载为 CSV。导入页面上的
238 **Recent imports** 列表也会实时更新。
239
240各行独立处理：一条错误的引用绝不会让整个文件失败。旧地址
241（`/admin/csv-import`、`/admin/materials-import`）会重定向到此处。
242
243每个实体的示例文件都与演示数据相互匹配，位于
244[`docs/import-samples/`](import-samples/README.md)。

262<a id="system-settings"></a>
263## 系统设置
264
265前往 **Settings → System**（仅 Admin）。
266
267<a id="production-period"></a>
268### 生产周期
269
270控制工单是否必须指定周或月编号：
271
272| 值 | 行为 |
273|---|---|
274| `none` | 不要求周期 |
275| `weekly` | 所有工单都必须有周编号 |
276| `monthly` | 所有工单都必须有月编号 |
277
278<a id="overproduction"></a>
279### 超产
280
281`allow_overproduction`：启用后，操作员可以在工单上生产超出计划的数量。禁用后，批次完成表单会把计划数量作为上限强制执行。
282
283<a id="sequential-steps"></a>
284### 顺序工序
285
286`force_sequential_steps`：启用后，操作员必须按既定顺序完成工序。禁用后，工序可以任意顺序完成。
287
288<a id="configuration-and-scenario-files-settings--system--data"></a>
289### 配置与场景文件（Settings → System → Data）
290
291Data 标签页上的 **Import**（仅 Admin）接收一个 JSON 文件，内含工厂配置、
292示例生产历史，或两者兼有。文件在一个事务中应用：只要 `scenario` 中有
293任何一处失败，文件里的内容就全都不保存，并且报错信息会指出失败的条目。
294**Export** 以相同的结构写出配置。
295
296要用一个文件干净地测试，请在同一标签页点击 **Reset system**，然后导入
297配置文件，再设置场景所需的生产流模式（Settings →
298Production），最后导入场景文件。
299
300**配置。** 每张表一个数组（`warehouses`、`lines`、`workstations`、`material_types`、
301`materials`、`product_types`、`line_product_type`、`process_templates`、`template_steps`、
302`bom_items`、`lot_sequences`、`label_templates`、`scrap_reasons`、`shifts`……），外加
303`system_settings`（形如 `key: value`）。
304
305- 行的 `id` 是文件内部的引用。外键指向这些 id，例如工位的
306 `line_id` 或 BOM 条目的 `template_step_id`。它们会被重映射为这些行在
307 当前数据库中实际获得的 id，因此文件从不依赖数据库自身的编号。
308- 行按其自然键匹配：一个编码、一个名称，或某个组合，例如工艺路线的
309 产品和名称、或工序的工艺路线和编号。再次导入同一个文件会更新行，
310 而不是重复创建。
311- 表按依赖顺序应用，与文件使用什么顺序无关。未知列会被忽略。
312- 设置沿用设置表单自身的键。基础设施与安全相关的键绝不会从文件读取，
313 生产流模式同样如此：请在 **Settings → Production** 中切换，因为它的
314 校验在那里运行。只有合法的时区才会被采用。
315
316```json
317{
318 "system_settings": { "language": "pl", "app_timezone": "Europe/Warsaw" },
319 "lines": [{ "id": 1, "code": "L1", "name": "Line 1" }],
320 "workstations": [{ "id": 1, "code": "ST-A", "name": "Assembly", "line_id": 1,
321 "operator_screens": ["queue", "workstation", "unit_labels"] }],
322 "product_types": [{ "id": 1, "code": "PRD-A", "name": "Product A" }],
323 "process_templates": [{ "id": 1, "product_type_id": 1, "name": "Routing A", "is_active": true }],
324 "template_steps": [{ "id": 1, "process_template_id": 1, "step_number": 1,
325 "name": "Assemble", "workstation_id": 1 }]
326}
327```
328
329**生产场景。** `scenario` 段在配置之上重放车间工作。每个事件都走
330操作员界面所用的同一个服务，因此状态、数量、消耗与单元历史都会
331像产线真实产出那样生成。时钟会被设定为每个事件的时间，所以时长和
332等待时间看起来就像真实的一个班次。
333
334- `requires.production_flow_mode` 使导入在另一种流模式下拒绝运行。
335- `users` 创建账户：`username`、`name`、`role`、`lines`、`workstation` 与
336 `password`；`"account_type": "workstation"` 表示某个工作台自己的终端登录，锁定
337 到它的 `workstation`。已存在的账户按原样使用，绝不会被修改。
338- `material_lots` 添加批次：`material` 是编码，另加 `lot_number`、`quantity`
339 与 `received`。
340- `events` 是时间线。每个事件都有 `do` 和 `at`。执行者是 `by`；省略 `by`
341 时由执行导入的管理员担任。配置通过编码引用。
342
343事件时间相对于导入时刻，并且必须按时间先后排列：
344
345| `at` | 含义 |
346|---|---|
347| `-2d 07:30` | 导入前两天，07:30 |
348| `-3h20m` | 导入前 3 小时 20 分 |
349| `+4m` | 上一个事件之后 4 分钟 |
350| *(省略)* | 上一个事件之后 10 秒 |
351
352事件发生在过去。只有调度窗口和截止日期可以位于将来，例如 `+1d 06:00`。
353
354| `do` | 字段 | 执行界面上的相同操作 |
355|---|---|---|
356| `work_order` | `order_no`、`product`、`line`、`quantity`、`due`、`customer_order_no`、`description` | 创建工单 |
357| `schedule` | `order`、`start`、`end`、`line`、`shift`、`force` | 将其放入排程器；除非 `force`，否则产线上的时间重叠会被拒绝 |
358| `batch` | `order`、`quantity`、`lot`（`auto` 自动抽取一个）、`workstation` | 下达一个批次 |
359| `step_start` / `step_log` / `step_complete` | `order`、`batch`（默认 1）、`step`；日志用 `good`、`scrap`、`note` | 开始、记录并结束一道工序 |
360| `unit_start` | `order`、`ref`、`psn`（`auto` 自动抽取一个）、`workstation` | 在其 PSN 上启动一个单元 |
361| `subassembly` | `order`、`material`、`sn`、`ref`、`workstation` | 在子组件制造处以它自己的序列号登记一个子组件 |
362| `unit_serial` | `unit`、`sn`（`auto`）、`workstation` | 把 SN 标签绑定到单元 |
363| `component` | `unit`、`identifier`、`material`、`step`、`workstation` | 把组件扫描进单元 |
364| `test` | `unit`、`workstation`、`result`、`steps`（`name`、`value`、`unit`、`low`、`high`、`verdict`）、`duration_s` | 登记一次测试机的运行；失败测试策略生效 |
365| `block` / `unblock` / `scrap` | `unit`、`reason`（`block` 用错误码）、`note`、`workstation` | 冻结、释放或报废一个单元 |
366| `pack` | `unit`、`workstation`、`weight_g`、`pallet` | 在包装台扫描单元；纸箱会自动打开 |
367| `carton_close` | `order`、`pallet`、`workstation` | 关闭打开的纸箱并放到托盘上 |
368| `pallet_open` / `pallet_close` / `pallet_ship` | `order`、`ref`、`pallet`、`workstation` | 创建、关闭或发运一个托盘 |
369
370`unit` 和 `pallet` 接受单元或托盘创建时给出的 `ref`，或它的真实编号。
371
372```json
373{
374 "scenario": {
375 "requires": { "production_flow_mode": "transfer" },
376 "users": [{ "username": "op-a", "name": "Operator A", "role": "Operator", "lines": ["L1"], "password": "…" }],
377 "events": [
378 { "at": "-1d 07:00", "do": "work_order", "order_no": "WO-1", "product": "PRD-A", "line": "L1", "quantity": 2 },
379 { "at": "+1m", "do": "batch", "order": "WO-1", "quantity": 2 },
380 { "at": "+2m", "do": "step_start", "order": "WO-1", "step": 1, "by": "op-a" },
381 { "at": "+1m", "do": "unit_start", "order": "WO-1", "ref": "u1", "workstation": "ST-A", "by": "op-a" },
382 { "at": "+5m", "do": "step_log", "order": "WO-1", "step": 1, "good": 1, "by": "op-a" },
383 { "do": "schedule", "order": "WO-1", "start": "-1d 07:00", "end": "-1d 15:00" }
384 ]
385 }
386}
387```

391<a id="warehouses"></a>
392## 仓库
393
394仓储是一个可选模块——在 **Settings → System → Modules** 下启用 **Warehouses**（见 [模块](#modules)）。关闭时，下面的页面会被隐藏，本节内容均不适用。
395
396> 在已有的生产环境上推这个功能？请遵循
397> [Warehouses & ERP Sync rollout runbook](warehouse-erp-rollout.md)——它涵盖
398> 部署顺序、加载期初库存、验收测试与回滚路径。
399
400<a id="setting-up-warehouses"></a>
401### 设置仓库
402
4031. 前往 **Admin → Production → Warehouses → All Warehouses**
4042. 点击 **+ New Warehouse**，为它设置 **code**、**name** 和 **kind**：
405 - **Raw materials** —— 物料从这里发出
406 - **Finished goods** —— 成品从这里收入
407 - **Mixed** —— 两者皆是
4083. 可选地设置 **ERP code** —— 同一仓库在你 ERP 中的标识符，这样库存同步和单据可以在两边对上
4094. 在「导入或自动生成单据未指定仓库时」应使用的那个仓库上勾选 **Default for its kind**
410
411在你依赖自动单据生成之前，请为原材料和成品各设置一个默认仓库——没有默认值，就什么都不会生成。
412
413**Admin → Production → Warehouses → Stock On Hand** 显示实时余额。**Lot** 列为空的行（显示为 *total*）是该物料在该仓库中的总量；带有批次的行是它的明细——不要把两者相加。
414
415仍存有库存或携带单据的仓库无法删除；请改为停用它。
416
417<a id="stock-documents"></a>
418### 库存单据
419
420**Admin → Production → Warehouses → Stock Documents** 列出仓库单据：
421
422| 类型 | 含义 |
423|---|---|
424| **Material release** | 原材料离开仓库投入生产 |
425| **Material receipt** | 原材料入库（ERP 收货、从车间退回） |
426| **Product receipt** | 工单结束时成品入库 |
427| **Product release** | 成品出库（发运、更正） |
428
429每张单据在过账前都是**草稿**，而**过账才会移动库存**——它会更新仓库余额、物料的库存数量和库存变动台账。**取消已过账单据会将其全部冲销**，这样无需手工编辑余额即可撤销错误。已过账单据必须先取消才能删除。
430
431**完成工单会自动生成其单据**（草稿）：一张针对所消耗物料的材料出库单——取自车间实际登记的批次，若没有则按工单 BOM × 生产数量计算——以及一张针对所生产成品的成品入库单。在此页面上审核并过账它们。要关闭生成功能，请在 `.env` 中设置 `WAREHOUSE_AUTO_DOCUMENTS=false`。
432
433用 **+ New Document** 手工创建单据：选择类型、仓库，然后每个物料添加一行。物料选择器会随类型变化——物料单据列出物料，成品单据列出产品。
434
435<a id="syncing-stock-with-an-erp"></a>
436### 与 ERP 同步库存
437
438同时启用 **Warehouses** 和 **ERP integration** 模块后，ERP 可以通过 REST API 让 OpenMES 保持同步：
439
440- **push balances** —— 按仓库和物料推送数量快照；仓库归 ERP 所有，因此同步的数量会替换 OpenMES 的数值，重复运行同步会收敛而不是漂移
441- **push lots** —— 推送批次号及其可用数量
442- **pull documents** —— 拉取 ERP 尚未记账的已过账出库单与入库单积压，然后用 ERP 自己的单据编号逐条确认，使其离开积压
443
444在 **Admin → API keys** 下创建一个带有 `erp:stock:read` /
445`erp:stock:write` 作用域的密钥（产品、物料、批次和配方还需要
446`erp:masterdata:write`）。端点、负载与作用域见：
447[API 文档 → ERP Integration API](API_DOCUMENTATION.md#erp-integration-api)。
