87## 本地开发环境搭建
88
89### 环境要求
90
91- Docker 与 Docker Compose
92- PHP 8.3（用于在本地不依赖 Docker 运行 artisan 命令）
93- Composer
94- Node.js 20+ 与 npm
95
96### 第 1 步：启动环境
97
98```bash
99git clone https://github.com/Mes-Open/OpenMes.git
100cd OpenMes
101docker-compose up -d
102```
103
104打开 `http://localhost` 并完成 Web 安装向导。
105
106### 第 2 步：安装依赖（用于开发）
107
108```bash
109cd backend
110composer install
111npm install
112npm run dev # starts Vite dev server with HMR
113```
114
115### 第 3 步：运行 Artisan 命令
116
117```bash
118# Inside Docker
119docker compose exec backend php artisan <command>
120
121# Or if PHP is installed locally
122cd backend
123php artisan <command>
124```
125
126### 常用命令
127
128```bash
129# Run tests
130php artisan test
131
132# Run tests with coverage
133php artisan test --coverage
134
135# Reset and re-seed the database
136php artisan migrate:fresh --seed
137
138# Load sample data
139php artisan db:seed --class=SampleDataSeeder
140
141# Clear all caches
142php artisan optimize:clear
143
144# Run code formatter
145./vendor/bin/pint
146```

150<a id="architecture-overview"></a>
151## 架构总览
152
153<a id="laravel-application-structure"></a>
154### Laravel 应用结构
155
156OpenMES 遵循标准的 Laravel 约定，并做了一些补充：
157
158**Web 控制器**（`app/Http/Controllers/Web/`）按角色划分：
159- `Web/Admin/` —— 管理后台控制器
160- `Web/Supervisor/` —— 主管控制器
161- `Web/Operator/` —— 操作员控制器
162
163**API 控制器**（`app/Http/Controllers/Api/V1/`）负责 REST API。
164
165**Services**（`app/Services/`）存放可复用的业务逻辑：
166- `ModuleManager` —— 发现、启用、禁用、安装与卸载模块
167- 其他处理复杂操作的服务（导入处理、批次创建等）
168
169**Livewire 组件**（`app/Livewire/`）是用于实时 UI 部分（例如仪表盘指标、实时搜索）的响应式组件。
170
171<a id="database-schema-overview"></a>
172### 数据库架构总览
173
174核心实体及其关系：
175
176```
177Factory → Division → Line → Workstation
178 ↓
179 WorkOrder → ProcessTemplate → TemplateStep
180 ↓
181 Batch → BatchStep (one per TemplateStep)
182 ↓
183 Issue → IssueType
184```
185
186其他表：
187- `users` —— 认证、Spatie 角色
188- `workers` —— 车间工人（独立于用户账号）
189- `crews`、`skills`、`wage_groups` —— 人力资源
190- `shifts` —— 工时定义
191- `audit_logs` —— 不可变的变更历史
192- `event_logs` —— 系统事件
193- `csv_imports`、`csv_import_mappings` —— 批量导入历史与配置方案
194- `system_settings` —— 键/值配置存储
195- `line_statuses` —— 可配置的产线状态码
196
197<a id="role-based-access-control"></a>
198### 基于角色的访问控制
199
200角色由 Spatie Laravel Permission 管理：
201
202```php
203// In controllers
204$this->middleware('role:Admin');
205$this->middleware('role:Supervisor|Admin');
206
207// In Blade templates
208@hasrole('Admin')
209 <admin-only-content/>
210@endhasrole
211
212@hasanyrole('Supervisor|Admin')
213 <supervisor-and-admin-content/>
214@endhasanyrole
215```
216
217三个主要角色：
218- `Admin` —— 完整的系统访问权限
219- `Supervisor` —— 生产管理，但不能做系统配置
220- `Operator` —— 仅自己的产线，无管理视图

224<a id="module-system"></a>
225## 模块系统
226
227模块是位于项目根目录 `modules/` 下的自包含 Laravel 包。它们由核心应用自动发现并加载。
228
229<a id="module-structure"></a>
230### 模块结构
231
232```
233modules/
234└── MyModule/
235 ├── module.json # Required: module metadata
236 ├── Providers/
237 │ └── MyModuleServiceProvider.php # Required: registers everything
238 ├── Controllers/
239 │ └── MyModuleController.php
240 ├── Models/
241 │ └── MyEntity.php
242 ├── views/
243 │ └── index.blade.php
244 ├── migrations/
245 │ └── 2025_01_01_000001_create_my_table.php
246 └── Console/
247 └── MyCommand.php
248```
249
250### module.json
251
252```json
253{
254 "name": "MyModule",
255 "display_name": "My Module",
256 "description": "A short description of what this module does.",
257 "version": "1.0.0",
258 "author": "Your Name"
259}
260```
261
262<a id="service-provider-registration"></a>
263### 服务提供者注册
264
265`ModuleManager` 通过扫描 `modules/*/Providers/*ServiceProvider.php` 发现模块。要加载某个模块，必须注册它的服务提供者。
266
267创建 `modules/MyModule/Providers/MyModuleServiceProvider.php`：
268
269```php
270<?php
271
272namespace Modules\MyModule\Providers;
273
274use Illuminate\Support\ServiceProvider;
275
276class MyModuleServiceProvider extends ServiceProvider
277{
278 public function boot(): void
279 {
280 // Register routes
281 $this->loadRoutesFrom(__DIR__ . '/../routes/web.php');
282
283 // Register Blade views (access via my-module::view-name)
284 $this->loadViewsFrom(__DIR__ . '/../views', 'my-module');
285
286 // Register migrations
287 $this->loadMigrationsFrom(__DIR__ . '/../migrations');
288
289 // Register Artisan commands
290 if ($this->app->runningInConsole()) {
291 $this->commands([
292 \Modules\MyModule\Console\MyCommand::class,
293 ]);
294 }
295 }
296}
297```
298
299<a id="adding-sidebar-navigation"></a>
300### 添加侧边栏导航
301
302模块可以通过挂接 `MenuRegistry` 往侧边栏添加条目：
303
304```php
305use App\Services\MenuRegistry;
306
307// Inside boot() method:
308MenuRegistry::add('my-module', [
309 'label' => 'My Module',
310 'icon' => '<svg .../>',
311 'route' => 'my-module.index',
312 'role' => 'Admin', // or 'Supervisor|Admin', 'Operator|Supervisor|Admin'
313]);
314```
315
316<a id="module-database-migrations"></a>
317### 模块数据库迁移
318
319把迁移文件放到 `modules/MyModule/migrations/`。它们与 Laravel 迁移格式一致：
320
321```php
322<?php
323
324use Illuminate\Database\Migrations\Migration;
325use Illuminate\Database\Schema\Blueprint;
326use Illuminate\Support\Facades\Schema;
327
328return new class extends Migration {
329 public function up(): void
330 {
331 Schema::create('my_module_entities', function (Blueprint $table) {
332 $table->id();
333 $table->foreignId('work_order_id')->constrained()->cascadeOnDelete();
334 $table->string('name');
335 $table->timestamps();
336 });
337 }
338
339 public function down(): void
340 {
341 Schema::dropIfExists('my_module_entities');
342 }
343};
344```
345
346运行迁移：`php artisan migrate`
347
348<a id="extending-core-models"></a>
349### 扩展核心模型
350
351要从模块给核心模型（如 WorkOrder）添加关系，使用服务提供者的 `boot()` 方法：
352
353```php
354use App\Models\WorkOrder;
355use Modules\MyModule\Models\MyEntity;
356
357WorkOrder::resolveRelationUsing('myEntities', function (WorkOrder $model) {
358 return $model->hasMany(MyEntity::class);
359});
360```
361
362现在 `$workOrder->myEntities` 在整个应用中都可用了。

366<a id="hook-system"></a>
367## 钩子系统
368
369OpenMES 在生产生命周期中触发 Laravel 事件。模块监听这些事件，从而在不修改核心代码的情况下对变化做出响应。
370
371完整可用事件列表与示例见 [HOOKS.md](../HOOKS.md)。
372
373### 快速示例
374
375在模块中监听工单完成：
376
377```php
378// In MyModuleServiceProvider::boot()
379use App\Events\WorkOrder\WorkOrderCompleted;
380
381Event::listen(WorkOrderCompleted::class, function ($event) {
382 $workOrder = $event->workOrder;
383 // Send ERP notification, update inventory, etc.
384});
385```

389<a id="frontend"></a>
390## 前端
391
392OpenMES 使用**服务端渲染的 Blade 模板**，配合：
393
394- **Tailwind CSS 4** —— 工具类优先的 CSS（经 Vite 编译）
395- **Alpine.js** —— 用于交互组件的轻量响应式能力
396- **Livewire 4** —— 全栈响应式组件（表单、实时表格）
397- **Chart.js** —— 仪表盘图表
398
399### Tailwind 深色模式
400
401应用通过 `<html>` 上的 `dark` 类支持深色模式：
402
403```html
404<!-- Dark mode styles -->
405<div class="bg-white dark:bg-gray-900 text-gray-900 dark:text-white">
406```
407
408深色模式偏好存储在 `localStorage` 的 `theme` 键下。
409
410### Alpine.js 状态
411
412侧边栏状态（`collapsed`、分组展开/收起状态）在布局根部的 `x-data` 中管理。持久化的侧边栏折叠状态存储在 `localStorage` 的 `sb` 键下。
413
414### 在模块中添加视图
415
416模块中的 Blade 视图使用服务提供者中注册的命名空间：
417
418```php
419// In ServiceProvider
420$this->loadViewsFrom(__DIR__ . '/../views', 'my-module');
421```
422
423```php
424// In controller
425return view('my-module::index', compact('data'));
426```
427
428扩展主布局：
429
430```blade
431@extends('layouts.app')
432
433@section('title', 'My Module Page')
434
435@section('content')
436 <div class="max-w-4xl mx-auto">
437 {{-- your content --}}
438 </div>
439@endsection
440```

444<a id="api-development"></a>
445## API 开发
446
447### 添加新的 API 端点
448
4491. 在 `app/Http/Requests/` 中创建 Form Request
4502. 在 `app/Http/Controllers/Api/V1/` 中创建控制器
4513. 在 `routes/api.php` 的 `v1` 分组内添加路由
4524. 使用 `auth:sanctum` 中间件（该分组已应用）
4535. 编写 Feature 测试
454
455### Form Request 校验
456
457始终使用 Form Request，绝不在控制器内联校验：
458
459```php
460class StoreWorkOrderRequest extends FormRequest
461{
462 public function authorize(): bool
463 {
464 return $this->user()->hasRole('Admin');
465 }
466
467 public function rules(): array
468 {
469 return [
470 'order_no' => ['required', 'string', 'unique:work_orders,order_no'],
471 'quantity' => ['required', 'integer', 'min:1'],
472 'due_date' => ['nullable', 'date', 'after:today'],
473 ];
474 }
475}
476```

480<a id="testing"></a>
481## 测试
482
483OpenMES 使用 Laravel 内置的测试框架。测试位于 `backend/tests/`。
484
485```bash
486# Run all tests
487php artisan test
488
489# Run a specific test file
490php artisan test tests/Feature/WorkOrderApiTest.php
491
492# Run with coverage report
493php artisan test --coverage
494```
495
496### 测试约定
497
498每个功能都必须有覆盖以下内容的测试：
4991. 正常路径（Happy path）
5002. 校验错误（字段缺失/非法）
5013. 鉴权（未认证 + 错误角色）
5024. 边界情况
503
504示例测试：
505
506```php
507class WorkOrderApiTest extends TestCase
508{
509 use RefreshDatabase;
510
511 public function test_admin_can_create_work_order(): void
512 {
513 $admin = User::factory()->create()->assignRole('Admin');
514
515 $response = $this->actingAs($admin)->postJson('/api/v1/work-orders', [
516 'order_no' => 'WO-TEST-001',
517 'quantity' => 100,
518 ]);
519
520 $response->assertCreated()
521 ->assertJsonPath('data.order_no', 'WO-TEST-001');
522
523 $this->assertDatabaseHas('work_orders', ['order_no' => 'WO-TEST-001']);
524 }
525
526 public function test_operator_cannot_create_work_order(): void
527 {
528 $operator = User::factory()->create()->assignRole('Operator');
529
530 $this->actingAs($operator)
531 ->postJson('/api/v1/work-orders', ['order_no' => 'WO-X', 'quantity' => 1])
532 ->assertForbidden();
533 }
534}
535```

539<a id="code-style"></a>
540## 代码风格
541
542提交前运行：
543
544```bash
545./vendor/bin/pint
546```
547
548Pint 使用 Laravel 预设（基于 PSR-12）。CI 会强制格式检查 —— 如果 `pint --test` 报告有改动，PR 将失败。
549
550### 关键约定
551
552- 禁止带用户输入的裸 SQL —— 始终使用 Eloquent 或 Query Builder
553- 禁止在控制器中内联校验 —— 始终使用 Form Request
554- 控制器中不放业务逻辑 —— 移到 Services 或模型方法
555- 可复用逻辑放在 `app/Services/`
556- 多步骤数据库操作使用事务
557- 记录安全事件（认证失败、权限拒绝）
