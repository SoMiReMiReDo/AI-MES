1# PostgreSQL test failures — 2026-09-16
2
3The nine failures previously reproduced on baseline `cca82cab` had four causes.
4
5| Area | Failures | Cause and fix |
6| --- | ---: | --- |
7| Invalid timezone fixture | 1 | The test inserted a bare string into a JSON column. Encode the deliberately unknown timezone as JSON; application timezone logic is unchanged. |
8| Preset installer | 4 | Tests forced the SQLite preset while the suite supplied PostgreSQL connection settings. Use the suite's actual driver so both supported presets are exercised in their respective runs. |
9| Sample-data replacement | 3 | Tests mocked schema replacement/seeding but still purged the real connection, rolling back their uncommitted fixtures. Mock both connection resets alongside the mocked Artisan work. |
10| Expired demo tenant pruning | 1 | Real PostgreSQL cascade-order issue: clearing a checklist's user reference could run after its batch disappeared. Delete the expired tenant's users first, then the tenant, within the same transaction. |
11
12## Additional regression coverage
13
14- Pruning removes the expired tenant, its users, batches and checklists while keeping unrelated users.
15- A retained machine-counter reference blocks deletion and rolls back user deletion; another
16 eligible tenant can still be pruned. Audit retention is not bypassed.
17- A separate integration test performs **real** schema replacement and seeding without a
18 surrounding test transaction. It checks removal of the old admin, the replacement admin's
19 password, Admin role and authenticated session, bakery product data, and installed modules.
20- The replacement test discards its disposable database during cleanup rather than running
21 historical downgrade migrations. Production downgrade support is not established by this test.
22
23## Scope
24
25The only application behavior change is the transaction ordering in `tenants:prune`.
26Production counting, flow settings, timezone behavior and sample-data replacement code are unchanged.
27No schema migration is required for this fix.
28
29Tests run against disposable databases and source snapshots containing only tracked project
30files plus this change's new integration test. Unrelated untracked workspace changes are excluded.
31The test runtime has GD WebP enabled, as in the preceding verification. This does not add WebP
32support to the repository's production image.
33
34A production-sized migration rehearsal was not performed: no production database copy is
35available. Functional migration tests cannot establish real-data locking duration or downtime.
