1# Planned production start
2
3Work orders have an optional `planned_start_at` date and time, expressed in the
4configured plant timezone. The field is available in the shared creation form,
5Admin/Supervisor edit forms, the planner editor and the work-order API.
6
7## Availability
8
9- A future start keeps the order out of the operator queue, workstation table,
10 their update checks and the operator work-order API list.
11- At the start instant, the order becomes available under the normal line,
12 station and status rules. This does not automatically start production.
13- An empty start retains immediate availability, including existing orders.
14- Visible operator pages refresh at most every 30 seconds and also react to live
15 changes. A tab refresh or returning to the tab rechecks availability.
16- Direct starts and output writes are guarded on the server, including batch
17 steps, whole-order quantities, shift entries, API transitions and machine
18 counting. Rejected shift writes leave no quantity entry behind.
19- Once production has started, moving its start into the future is rejected.
20 Planner undo follows the same rule. Scheduler writes and production entry
21 paths lock the order to serialize concurrent changes.
22
23## Scheduling
24
25`due_date` remains the delivery deadline. A primary planner move changes
26`planned_start_at` and preserves that deadline. A day/shift move uses the selected
27shift's start time, or midnight when no shift definitions exist; an hourly move
28sets an exact interval. Extra line segments retain their independent placement
29fields. Unscheduling preserves the deadline and release time while removing the
30line placement.
31
32For legacy orders without `planned_start_at`, the planner retains its existing
33placement fallback to the deadline/week. That fallback does not postpone operator
34availability. Capacity calculations and their drill-down use the planned start
35when present.
36
37Start-only orders show their actual start in the hourly view with an unspecified
38end. Their placeholder width does not represent a booked duration or conflict.
39No migration is required: the existing minute-planning columns and index are used.
40
41## Manual browser check (Polish UI)
42
431. In **Zlecenia → Nowe zlecenie**, select a line, set quantity to 10 and choose
44 **Operator (ręcznie)**. Set **Planowany start** to tomorrow at 08:15 and
45 **Termin** to a later date. The timezone is shown beside the start input.
462. Save and reopen the edit form. Confirm that date, time and deadline are retained.
473. In **Harmonogramowanie**, find the order on its start day. Move it to another
48 day/shift and reopen its editor: the start changes and the deadline remains.
494. Log in as an operator on that line. Confirm that this future order is absent
50 from **Kolejka** and **Stanowisko**, while an existing undated order is present.
515. As Admin, change the start to the next minute. Leave the operator workstation
52 visible. The order appears after the start, within the normal 30-second refresh.
536. Record one good piece using the appropriate whole-order or step action.
547. Try moving that started order to tomorrow. A validation message appears and
55 its saved start/output remain unchanged.
568. Test an empty start on a separate pending order: it is immediately available.
