1# 机器连通性架构
2
3本文档说明 OpenMES 如何连接到车间机器（MQTT、Modbus TCP、OPC UA）、读数如何流经系统，以及哪些内容是刻意留待以后处理的。目标读者是希望扩展连通性或新增协议的**贡献者**。
4
5日常的 MQTT 配置请参阅 [mqtt-connectivity.md](mqtt-connectivity.md)。
6

8
9## 核心思路：一条信号管道，多种协议
10
11每个协议适配器都是「笨」的：它只产生原始读数。所有含义都在一条与协议无关的单一管道中施加。这意味着新增协议**不会**触及状态、停机、OEE 或 UI 代码——你只需编写一个适配器，向接入器喂入数据。
12
13```
14[Machine] ──OPC UA──▶ [OPC UA gateway sidecar] ──HTTP──┐
15[Machine] ──Modbus──▶ [modbus:poll daemon (PHP)] ──────┤
16[Machine] ──MQTT────▶ [mqtt:listen daemon (PHP)] ──────┤
17 ▼
18 ┌─────────────────────────────────┐
19 │ MachineTag (address → signal, │
20 │ transform: scale/offset/value-map)│
21 └─────────────────────────────────┘
22 ▼
23 ┌─────────────────────────────────┐
24 │ MachineSignalIngestor │
25 │ routes by signal_type │
26 └─────────────────────────────────┘
27 ┌──────────────────────┼──────────────────────┐
28 ▼ ▼ ▼
29 MachineEvent WorkstationState counter deltas
30 (event store) (state machine) (good / reject)
31 ▼ ▼
32 auto ProductionDowntime per-workstation OEE
33 ▼
34 Live Machine Monitor
35```
36
37### 关键构件（`app/Services/Machine/`、`app/Models/`）
38
39| 组件 | 职责 |
40|---|---|
41| `MachineTag` | 把协议地址（Modbus 寄存器、OPC UA 节点 id、MQTT JSONPath）映射到一个 `signal_type` 和一个可选的 `transform`。 |
42| `MachineSignalIngestor` | 唯一入口。施加 transform，按信号类型（`state`、`good_count`、`reject_count`、`cycle_complete`、`telemetry`、`alarm`）分流。 |
43| `WorkstationStateMachine` | 按时间片开启/关闭 `WorkstationState` 行，并在进入/离开 `STOPPED`/`FAULT` 时自动创建/关闭 `ProductionDowntime`。 |
44| `MachineEvent` | 只追加的事件存储（correlation id、微秒级时间戳、用于边缘同步的 `synced_to_cloud`）。 |
45| `MachineMonitorService` | 实时监控器的读模型：当前状态、今日可用率、良品/不良品计数。 |
46| `RuntimeMonitor` | 跟踪每个连接的后台运行时是否存活（见下文）。 |
47
48### 信号类型
49
50标签声明了它的值*意味着*什么：
51
52- `state` → 驱动工位状态机（`RUNNING`/`IDLE`/`STOPPED`/`FAULT`/`SETUP`）。使用 `value_map` transform，例如 `{"1":"RUNNING","2":"IDLE","3":"FAULT"}`。
53- `good_count` / `reject_count` → 累积模式的机器计数器；接入器存储最后的值并发出**增量**。
54- `cycle_complete` → 视为良品计数脉冲。
55- `telemetry` → 存入当前状态元数据的数值（温度、压力……）。使用 `scale`/`offset`。
56- `alarm` → 真值会记录一条告警事件。

60## 支持的协议
61
62### MQTT — `php artisan mqtt:listen --connection=<id>`
63已完整实现（自 v0.4.0 起）。库：`php-mqtt/client`。参见
64[mqtt-connectivity.md](mqtt-connectivity.md)。
65
66### Modbus TCP — `php artisan modbus:poll --connection=<id>`
67已完整实现。库：`aldas/modbus-tcp-client`。
68
69- 配置位于 `modbus_connections`（host、port、unit id、轮询间隔、字节/字序）。UI：**Admin → Connectivity → Modbus**。
70- `ModbusReader` 解码 `int16/uint16/int32/uint32/float32/bool`，处理字节序和
71 Modicon 风格地址（`40001` → 寄存器 0）。
72- **无需硬件即可测试的模拟器：**
73 `php artisan modbus:simulate --port=5020` 会运行一个 PHP 内置的 Modbus TCP 服务器，让一台机器在 RUNNING/IDLE/FAULT 之间循环并递增计数器。把一行
74 `modbus_connections` 指向 `127.0.0.1:5020` 并运行轮询器，即可端到端地跑通整条管道。
75
76### OPC UA — 外部网关边车
77OpenMES **并不原生支持 OPC UA**——这是有意为之。OPC UA 是一种二进制协议，带有安全策略（Basic256Sha256）、X.509 证书以及安全通道/订阅模型，用 PHP 实现并不现实。生产上正确的做法是一个小巧的**网关边车**。
78
79- `opcua-gateway/`（Node.js、`node-opcua`）连接到 OPC UA 服务器，
80 订阅已配置的节点，并把归一化后的读数 POST 回 OpenMES。
81- 它使用与协议无关的桥接 API（`MachineGatewayController`）：
82 - `GET /api/v1/machine-connections/{id}/gateway-config` — 要订阅什么
83 - `POST /api/v1/machine-connections/{id}/signals` — 推送读数（会被接入）
84 - `POST /api/v1/machine-connections/{id}/heartbeat` — 保活
85- 任何外部系统（自定义 REST 推送器、边缘盒子）都可以使用同一套 API——
86 它并非 OPC UA 专用。
87- 配置位于 `opcua_connections`，UI：**Admin → Connectivity → OPC UA**。

91## 运行时可见性（项目硬性规则）
92
93> **任何需要后台守护进程或容器的功能，都必须在 UI 中体现该运行时是否真的在
94> 运行——因为并非所有人都用 Docker 部署。**
95
96一个已配置但没有任何轮询器/网关在运行的连接，会悄无声息地*什么都收不到*。为避免这种困惑：
97
98- 守护进程每个周期通过 `RuntimeMonitor::heartbeat()` 发出一次心跳；
99 OPC UA 网关在每次 POST 时发送心跳。
100- 连接页面会显示一个绿色的 **"running (last seen Ns ago)"** 横幅，或一个琥珀色的 **"not running"** 横幅，并附上可直接复制粘贴的启动命令，**同时**覆盖裸机（`php artisan …`）和 Docker（`docker compose --profile … up`）。
101- 实现于 `RuntimeMonitor` 以及
102 `resources/views/admin/connectivity/_runtime-status.blade.php` 分部视图。
103
104**当你新增一个协议/守护进程时：** 在守护进程循环中加入心跳调用，并在其连接页面上包含 `_runtime-status` 分部视图。

108## 运行后台服务（Docker，全部为可选启用）
109
110它们在 `docker-compose.yml` 中定义于可选启用的 profile 下，因此默认永不启动：
111
112```bash
113# Modbus poller for connection 1
114MODBUS_CONNECTION_ID=1 docker compose --profile connectivity up -d modbus-poller
115
116# OPC UA gateway for connection 1 (needs an API token: Admin → API Tokens)
117OPCUA_CONNECTION_ID=1 OPENMES_API_TOKEN=xxx \
118 docker compose --profile connectivity up -d opcua-gateway
119
120# MQTT listener for connection 1
121MQTT_CONNECTION_ID=1 docker compose --profile connectivity up -d mqtt-listener
122
123# Queue worker (needed in production for MQTT/queued jobs)
124docker compose --profile workers up -d queue-worker
125```
126
127不使用 Docker？在进程管理器（systemd、Supervisor 等）下运行等价的 `php artisan …` 命令。连接页面会显示确切的命令。

146## 有意推迟的内容（及原因）
147
148这些是**当前刻意不做的非目标**，而非缺失的工作。记录下来是为了让贡献者在接手前了解其中的取舍。
149
150### 1. 实时推送（Laravel Reverb / WebSockets）
151- **状态：** 实时机器监控器使用 **HTTP 轮询**（约 3 秒）。`realtime_mode` 设置（`polling`/`websocket`）已作为钩子存在。
152- **为何推迟：** 轮询不需要任何额外基础设施，对典型部署而言完全够用。Reverb 只有在同时存在许多大型 Andon 屏幕、或有严苛的亚秒级响应需求时才有回报。
153- **何时接手：** 当你需要真正的 Andon 看板或大量并发查看者时。添加 `laravel/reverb`、一个 `reverb` compose 服务，广播
154 `WorkstationStateChanged`，并把监控器接到 Echo 上，以轮询作为兜底。
155
156### 2. 回写机器（Modbus/OPC UA 写入）
157- **状态：** 按设计一切都是**只读**的。
158- **为何推迟：** 向正在生产的机器写入（设置参数、远程停机）是一项安全攸关的能力——一个 bug 就可能损坏设备或让生产停摆。只读是安全的默认值。
159- **何时接手：** 当存在具体用例时（例如从工单推送配方参数）。用专门的权限门控它，每次写入都添加一条审计日志，并默认关闭。
160
161### 3. 针对真实服务器的完整 OPC UA 测试
162- **状态：****接入路径**（网关 → OpenMES → 管道）已有测试覆盖；边车实际的 `node-opcua` 连接逻辑尚未在 CI 中针对真实的 OPC UA 服务器跑过。
163- **为何推迟：** 它需要在测试环境中有一台真实或容器化的 OPC UA 服务器（安全策略、证书、订阅）。
164- **何时接手：** 准备第一次真正的 OPC UA 部署时。启动一台测试服务器（例如 `open62541`/Prosys 演示容器），端到端验证边车。这是验证工作，不是缺失的代码。
