7## 架构——OpenMES 是客户端，不是 broker
8
9> **如果某个客户端「连不上 OpenMES」，请先读这一段。** OpenMES 是 MQTT
10> **订阅者（客户端）**——它**不是** MQTT broker。你不能让另一个
11> MQTT 客户端（MQTTX、HiveMQ demo、一台机器）「指向 OpenMES」并指望它能连上。
12
13MQTT 是**经由 broker** 的发布/订阅。每一个参与者——包括 OpenMES——
14都是连接到 *broker* 的客户端。因此你总需要一个 broker（例如
15[Eclipse Mosquitto](https://mosquitto.org)）居于中间：
16
17```
18[ machine / MQTTX / any publisher ] ──publish──▶ [ MQTT broker ] ◀──subscribe── [ OpenMES (php artisan mqtt:listen) ]
19 (Mosquitto)
20```
21
22- OpenMES 以**出站**方式连接到你在
23 **Admin → Connectivity → MQTT** 中设置的 broker 主机/端口
24 （`broker_host` / `broker_port`，默认 `1883`，
25 可选 TLS），并订阅你配置的主题。
26- 你的机器（或某个测试工具）向**同一个 broker** 发布。
27- OpenMES 从不为机器开放监听端口——它既不随附也不内嵌 broker。
28
29### 基于浏览器的测试客户端需要 WebSocket 监听器
30
31浏览器 MQTT 客户端——例如 **[MQTTX web client](https://mqttx.app/web-client)**
32和 **[HiveMQ WebSocket client](https://www.hivemq.com/demos/websocket-client/)**——
33只能说 **MQTT over WebSocket**（浏览器无法打开原始 TCP socket）。因此，仅监听
34TCP `1883` 的普通 broker 会**拒绝它们**——你必须在 broker 上启用一个
35**WebSocket 监听器**（习惯上端口为 `9001`，
36`protocol websockets`）。参见[步骤 1](#step-1--start-a-local-mosquitto-broker)，它
37同时配置了两个监听器。
38
39原生/桌面客户端（`mosquitto_pub`、MQTT Explorer、PLC、OpenMES 自身）使用
40原始 TCP 监听器（`1883`），**不需要** WebSocket 监听器。
41

44## 在生产环境运行 MQTT 监听器
45
46一个**单一的** `mqtt-listener` 服务（定义于 `docker-compose.yml`）同时监管**所有**活动的 MQTT 连接。它每隔几秒与数据库对账，因此当你在管理面板中**创建或激活一个新连接时，它会自动被接管**——无需重启，也没有每连接的容器。
47
48### 启动监听器
49
50```bash
51cd /opt/openmmes # or wherever your docker-compose.yml is
52docker compose up -d mqtt-listener
53```
54
55### 查看监听器日志
56
57```bash
58docker logs openmmes-mqtt-listener -f
59```
60
61### 停止监听器
62
63```bash
64docker compose stop mqtt-listener
65```
66
67监管器在每个对账周期做的事：
68
69- **新的/新激活的**连接 → 自动连接 + 订阅；
70- **已停用/已删除的**连接 → 断开；
71- 现有连接的 **broker 设置或主题发生变化** → 用新配置重连。
72
73> **固定到单个连接**（可选）：若要为单个连接运行专用进程，传入 `--connection=<id>`（例如 `php artisan mqtt:listen --connection=2`，或用 `MQTT_CONNECTION_ID` 把它加回 `mqtt-listener` 命令）。省略它则监管一切，这是推荐的默认做法。

96## 步骤 1 — 启动本地 Mosquitto broker
97
98这份配置开启**两个**监听器：TCP `1883`（供 OpenMES 和原生客户端使用）和
99WebSocket `9001`（供 MQTTX web / HiveMQ 等浏览器客户端使用）。两个端口都已发布。
100
101```bash
102docker run --name mosquitto-test -d -p 1883:1883 -p 9001:9001 eclipse-mosquitto:2 \
103 sh -c "printf 'listener 1883\nprotocol mqtt\nlistener 9001\nprotocol websockets\nallow_anonymous true\n' \
104 > /mosquitto/config/mosquitto.conf \
105 && mosquitto -c /mosquitto/config/mosquitto.conf"
106```
107
108> `allow_anonymous true` 仅用于本地测试——任何可被 localhost 之外访问的 broker
109> 都应要求凭据。
110
111如果在 Docker Compose 内运行，把 Mosquitto 连到与后端相同的网络：
112
113```bash
114docker network connect <your_project>_openmmes-network mosquitto-test
115```
116
117### 从浏览器客户端测试（MQTTX web / HiveMQ WebSocket）
118
119让浏览器客户端指向 broker 的 **WebSocket** 监听器——而不是 `1883`：
120
121| 字段 | 值 |
122|---|---|
123| 主机 | 你的 broker 主机（例如 `localhost` / 机器的局域网 IP） |
124| 端口 | `9001` |
125| 路径 | `/`（Mosquitto 的默认值） |
126| 协议 | `ws://`（若在前面加了 TLS 则为 `wss://`） |
127
128然后从该客户端**发布**到 OpenMES 订阅的某个主题（例如
129`factory/line1/machine01/status`），并观察它出现在监听器中（步骤 3–4）。
130记住两端必须使用**同一个 broker**——向公共 HiveMQ demo broker 发布的浏览器客户端，
131无法到达指向你本地 Mosquitto 的 OpenMES 实例。

135## 步骤 2 — 创建测试机器连接
136
137```bash
138docker compose exec backend php artisan tinker --execute="
139use App\Models\MachineConnection;
140use App\Models\MqttConnection;
141use App\Models\MachineTopic;
142use App\Models\TopicMapping;
143
144\$mc = MachineConnection::create([
145 'name' => 'TEST-MACHINE-01',
146 'protocol' => 'mqtt',
147 'is_active' => true,
148 'status' => 'disconnected',
149]);
150
151\$mqtt = MqttConnection::create([
152 'machine_connection_id' => \$mc->id,
153 'broker_host' => '172.21.0.5', // Mosquitto container IP
154 'broker_port' => 1883,
155 'clean_session' => true,
156 'qos_default' => 0,
157 'keep_alive_seconds' => 60,
158 'connect_timeout' => 10,
159 'reconnect_delay_seconds' => 5,
160 'use_tls' => false,
161]);
162
163\$topic = MachineTopic::create([
164 'machine_connection_id' => \$mc->id,
165 'topic_pattern' => 'factory/line1/machine01/#',
166 'payload_format' => 'json',
167 'is_active' => true,
168]);
169
170TopicMapping::create([
171 'machine_topic_id' => \$topic->id,
172 'action_type' => 'log_event',
173 'is_active' => true,
174]);
175
176echo 'Created MachineConnection ID=' . \$mc->id;
177"
178```

182## 步骤 3 — 验证连接（dry-run）
183
184`--dry-run` 标志会连接并记录收到的消息，但不把它们持久化到数据库——用于初次测试很安全。
185
186```bash
187docker compose exec backend php artisan mqtt:listen --connection=1 --dry-run
188```
189
190预期输出：
191```
192Starting MQTT listener for [1] TEST-MACHINE-01
193 Broker: 172.21.0.5:1883
194[18:56:27] Connected.
195 Subscribed: factory/line1/machine01/#
196```

200## 步骤 4 — 模拟一台机器发布数据
201
202从 Mosquitto 容器或任意 MQTT 客户端：
203
204```bash
205# Machine status message
206docker exec mosquitto-test mosquitto_pub \
207 -h 172.21.0.5 -p 1883 \
208 -t "factory/line1/machine01/status" \
209 -m '{"status":"running","speed":120,"temp":42.5,"cycle_count":1042}'
210
211# Production counter
212docker exec mosquitto-test mosquitto_pub \
213 -h 172.21.0.5 -p 1883 \
214 -t "factory/line1/machine01/production" \
215 -m '{"order_no":"WO-2026-001","produced":47,"planned":200}'
216
217# Alarm/fault
218docker exec mosquitto-test mosquitto_pub \
219 -h 172.21.0.5 -p 1883 \
220 -t "factory/line1/machine01/alarm" \
221 -m '{"code":"TEMP_HIGH","value":85.2,"threshold":80,"severity":"warning"}'
222```
223
224监听器会实时把收到的消息输出到控制台：
225
226```
227[2026-04-03T18:56:31+00:00] factory/line1/machine01/status: {"status":"running","speed":120,...}
228[2026-04-03T18:56:31+00:00] factory/line1/machine01/production: {"order_no":"WO-2026-001",...}
229```

233## 步骤 5 — 完整模式（带 DB 持久化）
234
235不带 `--dry-run` 运行，以处理消息并存入 `machine_messages`：
236
237```bash
238docker compose exec backend php artisan mqtt:listen --connection=1
239```
240
241验证消息已存储：
242
243```bash
244docker compose exec backend php artisan tinker --execute="
245use App\Models\MachineMessage;
246use App\Models\MachineConnection;
247
248echo 'Messages in DB: ' . MachineMessage::count() . PHP_EOL;
249MachineMessage::orderBy('received_at','desc')->take(3)->get(['topic','processing_status','received_at'])
250 ->each(fn(\$m) => print \"[\$m->received_at] [\$m->processing_status] \$m->topic\n\");
251
252\$c = MachineConnection::find(1);
253echo 'Total messages received: ' . \$c->messages_received . PHP_EOL;
254"
255```
256
257预期输出：
258```
259Messages in DB: 2
260[2026-04-03 18:56:46] [ok] factory/line1/machine01/production
261[2026-04-03 18:56:46] [ok] factory/line1/machine01/status
262Total messages received: 2
263```

282## 测试期间修复的已知问题
283
284最初的 WIP 提交在 `composer.json` 中声明了 `"php-mqtt/client": "^1.10"`——该版本并不存在（这个包从 `v0.x` 直接跳到 `v2.x`）。已修正为 `^2.0`。API 完全兼容（类名和方法签名相同）。
