25## Prerequisites
26
27To test PWA features, OpenMES must be served over **HTTPS** (or `localhost` for development). PWA features (service worker, install prompt) are blocked on plain HTTP connections unless you are on localhost.
28
29For production testing:
30- Use a valid SSL certificate
31- Ensure `APP_URL` in `.env` starts with `https://`
32
33For local development:
34- `http://localhost` is allowed by browsers for PWA testing
35- Use `http://localhost:8080` (or whatever port you configured)
36

39## Testing Environment Setup
40
41### Chrome Flags (useful for testing)
42
43Open `chrome://flags` and enable:
44- `#enable-desktop-pwas-remove-status-bar` — full-screen mode testing
45- `#bypass-app-banner-engagement-checks` — see the install prompt without needing real engagement
46
47### Clear Service Worker State
48
49Before each test run, clear the service worker state:
501. Open DevTools → Application → Service Workers
512. Click **Unregister** on any existing OpenMES service worker
523. Open Application → Storage → Click **Clear site data**

56## Installation Testing
57
58### iOS (Safari)
59
60**Steps:**
611. Open Safari on your iPhone or iPad
622. Navigate to your OpenMES URL
633. Tap the **Share** button (box with upward arrow)
644. Scroll down in the share sheet and tap **Add to Home Screen**
655. Confirm the name is "OpenMES" and tap **Add**
66
67**Expected result:**
68- An OpenMES icon appears on the home screen
69- Launching from the icon opens OpenMES in full-screen (no Safari browser chrome)
70- The theme color (`#1e40af`) appears in the status bar area
71
72**Known limitations on iOS:**
73- iOS requires HTTPS for full PWA support
74- Background sync is limited on iOS — actions queue locally and sync on next app open
75- Push notifications require iOS 16.4+
76
77### Android (Chrome)
78
79**Steps:**
801. Open Chrome on your Android device
812. Navigate to your OpenMES URL
823. Chrome should show an **"Add to Home Screen"** banner at the bottom
834. Tap **Install** (or use the menu → Add to Home screen)
84
85If the banner does not appear:
86- Open Chrome menu (⋮) → **Install app**
87- Or: Chrome menu → **Add to Home Screen**
88
89**Expected result:**
90- OpenMES icon appears in app drawer and can be pinned to home screen
91- Launching opens in standalone mode (no browser chrome)
92- App appears in Android Recent Apps with its own entry
93
94### Desktop Chrome/Edge
95
96**Steps:**
971. Navigate to your OpenMES URL in Chrome or Edge
982. Look for the install icon (📥) in the address bar
993. Click it and confirm installation
100
101**Expected result:**
102- OpenMES opens in its own window
103- Appears in the system's application list

107## Offline Mode Testing
108
109### Using Chrome DevTools
110
111This is the recommended approach for development testing.
112
1131. Open OpenMES in Chrome and log in
1142. Navigate to a page with data (e.g., work order queue)
1153. Open DevTools (F12)
1164. Go to **Application → Service Workers**
1175. Check the **Offline** checkbox
118
119**Test scenarios:**
120
121| Action | Expected Behavior |
122|---|---|
123| Reload the page | Page loads from cache (no network error) |
124| Navigate to a cached page | Page loads normally |
125| Navigate to an uncached page | Offline page (`/offline`) is shown |
126| Try to complete a step | Action is queued, shown as pending |
127| Try to report an issue | Action is queued, shown as pending |
128
1296. Uncheck **Offline** to restore the connection
1307. Verify: queued actions are automatically submitted within a few seconds
131
132### Physical Network Disconnection
133
134For real-device testing:
1351. Log in to OpenMES on your tablet
1362. Load the work queue page
1373. Disconnect from WiFi or enable Airplane Mode
1384. Verify an offline banner appears at the top of the screen
1395. Attempt to complete a production step
1406. Reconnect to WiFi
1417. Verify the completed step is synced

145## Service Worker Testing
146
147### Verify Registration
148
1491. Open DevTools → Application → Service Workers
1502. You should see `/sw.js` registered for your OpenMES origin
1513. Status should be **activated and running**
152
153### Cache Inspection
154
1551. Open DevTools → Application → Cache Storage
1562. You should see at least one cache named `openmmes-v1` (or similar)
1573. Inspect cached resources — should include core HTML, CSS, JS, and images
158
159### Update Flow
160
161To test service worker updates:
1621. Change a cached asset (e.g., modify a view)
1632. Rebuild assets: `npm run build`
1643. Reload the page twice (first load detects the new SW, second load activates it)
1654. Alternatively, in DevTools → Application → Service Workers, click **Update**

176 - **Short name**: OpenMES

214## Performance Testing
215
216For tablets on the shop floor, performance matters. Run a Lighthouse audit:
217
2181. Open DevTools → Lighthouse
2192. Select **Mobile** device simulation
2203. Check: **Performance**, **PWA**, **Best Practices**, **Accessibility**
2214. Click **Analyze page load**
222
223**Target scores:**
224- PWA: 100 (all installability checks pass)
225- Performance: ≥ 70 on a simulated mobile device
226- Best Practices: ≥ 90
227- Accessibility: ≥ 80
228
229### Network Throttling
230
231Simulate a slower factory WiFi connection:
2321. DevTools → Network → Throttling
2332. Select **Slow 3G** or **Fast 3G**
2343. Reload the page and measure time to interactive
235
236Target: main pages load within 3 seconds on Fast 3G.

240## Common Issues and Fixes
241
242### Install prompt does not appear
243
244- Ensure you are on HTTPS (not HTTP, except localhost)
245- Check the manifest is valid (DevTools → Application → Manifest)
246- The service worker must be registered and active
247- On Chrome, there must be at least one prior visit to the site (or bypass engagement checks via flags)
248
249### Service worker not updating
250
251- Hard-refresh with Ctrl+Shift+R
252- Or go to DevTools → Application → Service Workers → click **Update**
253- If still stuck: click **Unregister**, then reload
254
255### Offline page not showing
256
257- The `/offline` route must be cached by the service worker on first load
258- Check that the service worker's install event caches the offline page
259
260### Actions not syncing after reconnect
261
262- Check browser console for errors after going back online
263- Ensure Background Sync is supported in the browser (Chrome on Android supports it; Safari on iOS has limited support)
264- On iOS, sync happens when the app is opened, not automatically in the background
265
266### Dark theme not applying on install
267
268The theme color is set in both the manifest and a `<meta name="theme-color">` tag. If it doesn't apply, check that the meta tag is present in the `<head>` section of the main layout.
