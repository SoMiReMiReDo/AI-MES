# 半导体 MES + Agent + WebUI 系统规划 v0.1

日期：2026-11-10｜状态：方案草案，未实现。

目标是交付一套能通过 WebUI 完成晶圆批次执行、质量处置和设备追溯，并由 Agent 辅助查询与分析的系统。首版以单企业单厂的晶圆制造演示闭环为假设；具体工艺、封测范围与规模尚未确认。

单晶圆追溯、批次履历和 Recipe 管理是选取场景时的行业参考，见 [Siemens 半导体 MES 产品说明](https://www.siemens.com/en-us/products/opcenter/execution/semiconductor/)。以下模块与约束是本项目设计建议，不代表已满足工厂规范。

## 1. 首版业务闭环

准备产品与工艺版本 → 创建 Lot 及 Wafer 清单 → 投放工艺路线 → 设备校验与 Track-in → 记录加工/量测结果 → Track-out → 异常 Hold 与授权 Release → 后续工序 → 批次完成与追溯。

| 模块 | 首版 WebUI 与后端能力 | 后续扩展 |
| --- | --- | --- |
| 基础与权限 | 用户/角色、厂区/区域、产品、设备组、设备、原因码 | 企业 SSO、多厂/多租户 |
| 工艺与配方 | Route 版本、工序顺序、Recipe 版本引用及设备适用范围 | 配方文件下发、复杂分支与工艺变更审批 |
| Lot/Wafer | 建批、投放、晶圆身份、载具/槽位记录、WIP 查询 | 自动搬运、复杂载具调度 |
| 生产执行 | 派工列表、Track-in/out、执行记录、设备占用校验 | 多 Lot 共炉、Chamber 级调度、自动派工 |
| 异常与质量 | Lot Hold/Release、原因/处置、量测记录、Wafer 报废记录 | 单片 Hold、SPC/FDC/APC、复杂返工路线 |
| 拆合批与追溯 | 按 Wafer 拆批、受限合批、血缘与完整历史 | 跨路线合批、复杂实验批管理 |
| 设备 | 状态、状态履历、加工关联、模拟事件接入 | SECS/GEM、保养、设备资格、真实远程控制 |
| Agent 工作台 | 对话、批次查询、履历解释、异常摘要、来源链接 | SOP 检索、建议单及授权执行 |

首版数量按 Wafer 身份清单核算；Die 级良率、晶圆图与封测转换不作默认承诺。基础统计展示 WIP、Hold、设备状态和周期数据，先统一指标口径，再扩展良率/OEE。

## 2. 领域边界与关键约束

| 核心对象 | 必须区分的概念 |
| --- | --- |
| Lot / Wafer / LotMembership | Lot 是批次，Wafer 是持续追踪的个体；归属变化保留时间和血缘 |
| RouteVersion / OperationOccurrence | 工艺版本与步骤实例；同一工序重复出现时仍有不同步骤身份 |
| RecipeVersion / Equipment | 配方标识、修订版和适用设备；首版不存储或执行机器配方指令 |
| ProcessRun / TrackEvent | 一次实际加工及其人员、设备、工序、配方和时间；不能仅覆盖当前状态 |
| HoldRecord / Measurement / Disposition | Hold 与生产状态分开；保留多个 Hold 的原因、释放人和处置历史 |
| SplitMergeEvent / Genealogy | 拆合批关联及 Wafer 迁移；源批耗尽也保留历史身份 |
| AgentSession / ToolRun / AuditEvent | 对话、工具执行和业务审计相互关联，但不替代业务事实 |

关键不变量：

1. 同一 Wafer 同一时点只能属于一个有效 Lot；拆合批前后身份集合守恒，不能凭空增减。
2. Track-in 校验工序、设备状态/容量、Recipe 匹配、Hold 和用户权限；服务端判定能否执行。
3. Track-out 必须对应未结束的 ProcessRun。请求重试不得重复计数；并发使用版本检查和数据库约束。
4. 首版限制同一设备一次加工一个 Lot。多批共炉以后新增批处理模型，不能仅放开容量字段。
5. 首版拆合批仅允许未加工中的批次；合批要求产品、Route 版本、当前位置及相关 Recipe 约束一致，且无未解除 Hold。具体规则在需求阶段冻结。
6. 多个 Hold 必须分别解除；运行中新增 Hold 不改写已有加工事实，阻止下一步启动，并通过受控处置决定当前加工如何收尾。
7. 投放时绑定 Route 版本，执行时记录实际 Recipe 版本。后续主数据修改不得回写历史。
8. 批次完成和报废分别记录；状态变化、Wafer 归属、审计和待发事件在同一事务内提交。

## 3. 前后端架构

采用模块化单体：一个 ASP.NET Core API 承载业务入口，一个 Worker 处理持久化任务和事件；模块按身份、主数据、生产、质量、设备、追溯、Agent 组织。先保持单个 PostgreSQL 实例和清晰表归属。

| 层次 | 职责与调用方向 |
| --- | --- |
| React WebUI | 管理工作台、生产操作台、质量处置、设备页、追溯页、Agent 侧栏 |
| API | 身份、权限、参数校验、版本化契约、统一错误和追踪 ID |
| Application / Domain | 执行业务用例和状态约束；WebUI、Agent、设备接入共用规则 |
| Infrastructure | EF Core、数据库、外部适配、模型客户端、文件存储 |
| Worker | 消费数据库 Outbox、发送通知、导入/模拟设备事件；失败重试和死信记录 |
| PostgreSQL | 业务事实、履历、审计、会话及任务状态；知识向量后续扩展 |

前端通过 `/api/v1` 获取分页、筛选、排序后的数据；写接口携带幂等键与期望版本。401/403/409/参数错误应有明确界面反馈。OpenAPI 生成 TypeScript 客户端，避免手写两套 DTO。

首版同源部署，Identity + HttpOnly 安全 Cookie 登录，写请求校验防伪令牌；权限在服务端执行，按钮显隐仅辅助体验。SignalR 只推送已授权的数据变更通知；客户端首次加载、订阅完成和重连后重新查询，数据库是最终事实来源。

拟议目录（只规划，不创建）：`src/MESagent.Api`、`MESagent.Application`、`MESagent.Domain`、`MESagent.Infrastructure`、`MESagent.Agent`、`MESagent.Worker`；前端 `web/`，测试 `tests/`，部署 `deploy/`。现有控制台如何替换在工程初始化阶段处理。

## 4. Agent 与业务的连接

首批只读工具建议：`GetLotStatus`、`GetWaferHistory`、`GetEquipmentHistory`、`ListHeldLots`。工具返回结构化结果、数据时间和业务记录链接；数值统计由后端计算，模型负责解释。

- 使用当前用户及其数据范围执行工具，服务端注入身份，不能接受模型指定任意用户或厂区。
- 模型不可用时，常规 MES 页面和业务 API 仍能工作；工具调用设超时、次数及上下文大小限制。
- SOP 检索阶段按访问范围过滤文档，回答引用来源；文档内容不能覆盖工具权限。
- 后续写入先产生建议单，展示对象、前置条件与参数；授权人确认后重新检查权限和最新状态，再执行相同的应用层命令。
- 批次释放、报废、工艺变更和设备控制不允许由聊天文本直接触发。确认记录与参数绑定，重试保持幂等。
- 会话记录模型/提示版本、工具参数摘要、结果和耗时；日志脱敏，不存模型隐藏推理。

## 5. 分阶段交付与验收

以下均为未来计划，尚未启动；不在人员和规模未知时给出日历工期。

| 阶段 | 交付范围 | 验收依据 |
| --- | --- | --- |
| P0 需求与选型 | 具体工艺样本、角色矩阵、状态图、依赖兼容性计划 | 明确 Lot/Wafer、Track-in/out、拆合批及 Hold 规则 |
| P1 工程基础 | API/WebUI/数据库、登录、主数据、Compose 雏形 | 干净环境启动；前端调用真实 API；拒绝越权访问 |
| P2 生产闭环 | Lot/Wafer、工艺版本、设备、执行、质量、拆合批、追溯 | 一批晶圆走完示例路线；并发/重复提交不重复记账 |
| P3 Agent 辅助 | 查询工具、流式对话、异常解释与审计 | 回答可回溯到真实记录；拒绝越权工具请求；模型故障不影响 MES |
| P4 完整交付 | 镜像、迁移、演示数据、备份恢复、监控与操作文档 | 新机器部署并完成闭环；重启数据仍在；恢复演练通过 |
| P5 行业深化 | 实机联接、复杂返工、共炉、SPC、ERP、排程 | 基于实际设备与工厂验收条件另立范围 |

演示样本建议：一个包含 5 片 Wafer 的 Lot，经过 3 个演示步骤；制造一次 Hold、授权 Release、一次拆批及兼容位置合批，逐片查询全过程。步骤名称与参数仅作软件演示，待工艺人员提供业务样本后替换。

测试计划覆盖领域不变量、真实 PostgreSQL 事务与并发、API 权限、浏览器端全流程，以及 Agent 工具授权/事实引用。首版验收要求错误、空数据、加载和重连状态均可解释，不能仅有静态界面或模拟 API。

## 6. Docker 交付边界

- `web`：静态资源 + Nginx 同源反向代理；`api`：业务与 Agent；`worker`：后台任务；`postgres`：持久化数据。
- .NET SDK/Node 用于构建阶段，运行镜像只保留所需运行时和产物。标签与摘要固定，不用浮动 `latest` 交付。
- 数据库和密钥不上公网；数据库、必要附件和 Cookie Data Protection 密钥使用持久化存储，凭据由部署环境注入。
- 数据库迁移作为单次部署任务；应用健康检查区分进程存活与依赖就绪，服务自身处理数据库短暂不可用。
- 备份应离开应用宿主机；持久卷不是备份。发布前做恢复演练，并说明数据迁移后的回退策略。
- Compose 覆盖开发和单机试点，尚不承诺高可用。吞吐、RPO/RTO、多节点和内网模型部署在规模确定后设计。

SECS/GEM 可作为后续设备集成候选，相关协议族见 [PEER Group 说明](https://www.peergroup.com/resources/semi-standards/secs-gem/)。真实接入需取得设备接口资料并完成适配验证，首版模拟器不代表协议合规。
